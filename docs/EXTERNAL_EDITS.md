# 外部编辑恢复与清理

按 SECURITY §7 与 CONTRACTS §2，ExternalEdits 持有恢复记录和私有副本。结束编辑的确认由界面负责；用例的清理仍需满足以下约束。

- 结束编辑先停止该稿件的自动上传与 watcher，等待已开始上传收束，再尝试删除副本目录。最多重试 3 次，间隔 100 ms。成功后才移除恢复记录；失败时保留记录、禁用该稿自动上传并显示无法删除的副本路径，允许再次“结束编辑”。不得先移除记录再吞掉 IO 错误。
- 历史 ID 只能是安全 ASCII 文件名片段；本地副本必须直接位于数据目录 `edits/<id>/` 下。恢复时先校验，再安装 watcher、打开文件或清理。非法历史进入配置保护页，不静默跳过。操作前重新验证目录不是符号链接；不声称可防御控制当前 OS 用户的其他进程或消除所有路径替换竞态。
- 打开编辑器失败或成功打开后触发后续异常时，已经登记的稿件不能被 catch 分支删掉。保留它供重开和手动清理。
- 无法删除副本时，传输面板的编辑条目显示 `cleanupFailed` 对应的失败状态并保留“结束编辑”入口，该入口再次走同一清理。
- 自动测试（`test/external_edits_test.dart`，6 项）覆盖：结束时删除副本与记录；删不掉时保留记录、停止自动上传并可再次结束；瞬时失败先重试；并发结束共用一次清理；布局之外的历史进入配置保护页且不删除任何东西；副本目录被链接替换时拒绝穿过链接删除。
- 关窗保存和真实编辑器的原子替换/文件锁仍需作者环境验收；自动测试只验证受控失败与恢复记录，不将其描述成 F-05 已完成。
