# 外部编辑恢复与清理

按 SECURITY §7 与 CONTRACTS §2，ExternalEdits 持有恢复记录和私有副本。结束编辑的确认由界面负责；用例的清理仍需满足以下约束。

- 结束编辑先停止该稿件的自动上传与 watcher，等待已开始上传收束，再尝试删除副本目录。最多重试 3 次，间隔 100 ms。成功后才移除恢复记录；失败时保留记录、禁用该稿自动上传并显示无法删除的副本路径，允许再次“结束编辑”。不得先移除记录再吞掉 IO 错误。
- 历史 ID 只能是安全 ASCII 文件名片段；本地副本必须直接位于数据目录 `edits/<id>/` 下。恢复时先校验，再安装 watcher、打开文件或清理。非法历史进入配置保护页，不静默跳过。操作前重新验证目录不是符号链接；不声称可防御控制当前 OS 用户的其他进程或消除所有路径替换竞态。
- 打开编辑器失败或成功打开后触发后续异常时，已经登记的稿件不能被 catch 分支删掉。保留它供重开和手动清理。
- 无法删除副本时，传输面板的编辑条目显示 `cleanupFailed` 对应的失败状态并保留“结束编辑”入口，该入口再次走同一清理。
- 自动测试（`test/external_edits_test.dart`，6 项）覆盖：结束时删除副本与记录；删不掉时保留记录、停止自动上传并可再次结束；瞬时失败先重试；并发结束共用一次清理；布局之外的历史进入配置保护页且不删除任何东西；副本目录被链接替换时拒绝穿过链接删除。
- 关窗保存和真实编辑器的原子替换/文件锁仍需作者环境验收；自动测试只验证受控失败与恢复记录，不将其描述成 F-05 已完成。

## 默认打开方式与自动同步（2026-11-08）

- Windows 的远程普通文件右键提供“打开方式”，列出本地注册表关联且仍存在的应用、系统默认方式及手动选 exe。选中立即生效，双击同样可确认；“始终用于”默认勾选。按扩展名保存，Dockerfile、.bashrc 等按完整文件名保存，最多 256 种。
- 选择经 typed `EditorAppsNotifier.setDefault` 写 `editor_apps.json`（schema 1），不加入 AI 能力。损坏或未来版本保留原文件且不覆盖，读取可回落为空偏好；它不是启动必需配置，不进入全局阻断恢复页。保存失败返回类型化错误，不能假报已记住。
- 文件双击通过 `ExternalEdits.open` 使用已选默认；默认程序失效时尝试系统关联。刚明确选择的程序启动失败则报告失败，副本与记录保留。可运行扩展名不经系统直接执行；Windows 仅解析关联的安全 exe，并拒绝命令/脚本宿主。macOS/Linux 当前只走系统关联，没有应用枚举与可靠关闭跟踪，未实测。
- 每个新打开稿件 `autoUpload:true`；传输面板编辑条目显示“保存时自动上传”复选框，取消后不发起新的自动上传，已开始的上传正常收束；可手动上传。历史记录保持原来保存的开关值。
- 可靠跟踪只用于有文档等待语义的已识别编辑器：VS Code 系列通过自身 cli.js 与 ELECTRON_RUN_AS_NODE + --wait，Sublime 通过 subl.exe --wait。等待进程成功退出才算关闭；失败、系统转交和未知应用都保留稿件，不用存活时长猜文档是否关闭。
- 等待所有可靠启动关闭后再次检查最后一次保存，等待在途上传及有界追赶；仍为 clean 且没有其他启动/不确定编辑器时结束。重新打开期间不得由旧关闭回调删除副本。未同步、冲突、上传失败、恢复记录或不确定的转交均保留，用户手动处理/结束。
- `test/open_with_test.dart` 覆盖类型映射、持久化、注册表发现、脚本宿主拒绝和等待命令；`test/open_with_dialog_test.dart` 覆盖即时选择与默认重启读取；`test/editor_lifecycle_test.dart` 通过本机隔离临时目录与受控等待信号，验证最后保存先同步、关闭同步保留、冲突保留、重开竞态和不确定转交保留。与既有清理测试一起均通过完整回归。
- 本轮没有启动真实编辑器、没有连接服务器；修改后的 `integration_test/edits_test.dart` 未重新运行。应用枚举、作者编辑器的 --wait 行为、原生选择器和文件锁仍待真实环境验收，不将 F-05 勾选。

## 真实服务器记录（2026-11-07，历史行为）

`integration_test/edits_test.dart` 在 Windows 11 连 Ubuntu 服务器，文件只放在 `~/sshairy-test/edit-<id>`，结束后删除并断言已不存在。启动编辑器的程序经 `fileOpenerProvider` 换成记录器，由测试扮演“编辑器”，所以验证的是应用这一侧；某个编辑器的保存方式能否被 watcher 看到，仍要作者用自己的编辑器试（F-05 不勾选）。

两个流程通过：

- 下载副本在私有数据目录；原子替换（先删后建）被发现并标为已修改，未请求时不上传；手动上传后基线更新；开自动上传后原地写入自动上传；连续 8 次保存最终以最后一次为准，3 秒后无旧稿迟到上传。
- 服务器上的文件被改过时，上传停在冲突、不覆盖服务器、保留本地稿；“重新下载”、“强制覆盖”、“另存为副本”（命名为 `note (1).txt`，原文件不动，编辑改为跟随副本）各自生效；Windows 不接受的文件名（`a b:c 中文.txt`）存为 `a b_c 中文.txt` 并回传到原路径；再次打开同一文件复用副本，不覆盖草稿；结束编辑后副本目录为空。
- 退出时刚保存的内容在 watcher 延迟前也会被发现，退出本身不上传；重启后恢复为未保存、可上传，并重新被监视。

上述历史实测使用当时的 `fileOpenerProvider` 测试接缝；2026-11-08 已替换为 `editorLauncherProvider`，不能把旧服务器结果作为新打开方式与编辑器关闭跟踪的验收。
