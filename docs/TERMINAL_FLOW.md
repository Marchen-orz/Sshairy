# 终端输出流控

2026-11-07。落实 MODULES §3 的数据管线；实际服务器与交互验收仍以 ROADMAP T-03 为准。

每个 shell 独立持有输出消费器，stdout/stderr 各有增量 UTF-8 解码状态，共用按接收回调顺序排列的字节队列；不把未解析的字节丢弃、拼成应用状态通知或记录到日志。两条流之间没有 SSH 保证的全局顺序，只保留应用实际收到的顺序。

入口高水位 1 MiB、低水位 256 KiB。达到高水位时暂停两条输入订阅，消费到低水位后一起恢复；暂停沿 dartssh2 的 ShellChannel stream 传递到 channel 的接收窗口。入口把每个事件复制成独立、至多 8 KiB 的队列缓冲，消费完整缓冲后释放，避免 Uint8List 的视图继续持有已消费前缀或更大的上游 backing buffer。pendingBytes 统计队列尚未消费的载荷；retainedBytes 统计队列持有的 backing buffer 容量，二者在解析回调之间一致。暂停遵循订阅契约时，队列载荷上限为高水位加触发暂停的一个输入事件；正在解码的至多一个 8 KiB 缓冲、短暂的解码字符串、队列对象开销、库内 channel/window 缓冲及入口复制期间仍在调用栈上的上游事件另计，不能将此数值宣称为整个连接的内存硬上限。任意单个输入事件的大小不由消费器控制，当前 SSH 包大小与实际内存仍需实测。

每次最多解码/解析 64 KiB，按 8 KiB 分片检查 4 ms 时间预算，然后用事件队列定时器让出执行权。一次第三方 VT 解析不能被抢占，4 ms 是调度预算而非单次解析的硬实时承诺。使用普通事件定时器，不依赖绘制帧；隐藏标签与最小化窗口继续消费，回滚仍由 terminal model 上限约束。UTF-8 跨片段保留 decoder 状态，ANSI 跨片段交由 terminal parser 保留状态。

消费器属于 shell/model，不属于 view。正常 shell 结束后等流尾部和已排队内容排空再发布 disconnected，避免丢最后一屏输出。transport 结束则立即停止输入订阅，给尚未 EOF 的 decoder 排入结束标记，仅排空应用已经接收的尾部，不等待上游流另行 EOF；即使 shell 先结束而 transport 在等待尾部期间才丢失，也能收束并进入重连策略。transport 丢失后尚未交给应用的上游缓冲不保证保留。流出错停止消费并报告连接失败；用户关闭会话则取消订阅、定时器和待处理字节。正在连接的会话关闭时取消拨号等待。重连创建新消费器，旧 shell 的完成回调与输出必须经过身份检查，不能修改新 shell 的状态或内容。会话结束后取消订阅、关闭本 shell、归还其租约，不关闭共享 transport。

自动测试覆盖水位暂停/恢复、队列 buffer 容量与释放已消费前缀、不保留输入的更大 backing buffer、分片和事件间让出执行权、UTF-8 与 ANSI 跨片段、双流、结束排空、transport 丢失且流永不 EOF 时的收束与自动重连、错误与取消、会话关闭/重连的迟到输出。

`integration_test/app_test.dart` 的 “terminal flow” 在 Windows 11 经公网连 Ubuntu 服务器，持续输出 `yes`。链路约 3 Mbit/s 下行，所以消费端比链路快，测得的是链路上限而不是应用的上限。
