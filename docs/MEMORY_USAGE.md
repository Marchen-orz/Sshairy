# 运行内存与闲置资源（2026-11-08）

用户报告长时间使用后为 300–400 MB；本轮只读采样确认当前运行的是原目录 Release：WorkingSet64 为 330.3 MiB，PrivateMemorySize64 为 282.3 MiB（私有提交，非任务管理器私有工作集）。没有控制会话数量、目录数据或窗口大小，不能把该数字归因于某个缓存，或作为修复前后可比基线；新机制尚未测量出固定下降值。Dart 自动回收不可达对象，Flutter 也有图片 LRU 和内存压力清理；任务管理器数字包含渲染器、堆的保留容量等，释放对象不保证数字立即下降。

本轮按实际保留点收紧资源：

- 传输历史在内存和磁盘均遵守现有 200 条/30 天规则；活动任务与可恢复 checkpoint 不裁剪。一个批次不再有排队/运行/暂停待恢复任务时，释放其冲突选择。
- 底部目录树按 128 个目录/8192 个子项的目标回收缓存，折叠分支优先；当前路径及祖先的完整列表受保护，单个大目录可能超过目标，不截断目录内容，离开后即可回收。淘汰后展开时重新读取。文件浏览前进/后退历史分别最多 100 项。
- 文件页面不可见 30 秒后释放只为浏览服务的目录列表、监听和 SFTP 租约，保留连接目标/路径/排序等恢复所需元信息；返回页面重新读取。正在执行文件修改时延后回收；隐藏页面停止动画，挂起状态不显示加载动画。后台传输和外部编辑拥有自己的资源，不因浏览页面隐藏而中断。
- 应用装配层将闲置图片 LRU 限制到 16 MiB/128 项；窗口隐藏、最小化或系统内存压力时清理非活动图片缓存，不清除仍被 Widget 监听的图片，不制造重复解码。
- 终端仍保留用户配置的回滚行数；隐藏的会话不丢缓冲、不主动断开。监控保留最多 60 个采样，隐藏即停止采集。

不加定时强制 GC、不调用 Windows 工作集裁剪来制造短暂低读数。验证以有界状态、关闭/闲置释放和恢复行为测试为主；没有新的运行测量时，只报告机制与已验证行为。
