# 配置恢复与写保护

2026-11-07。补齐 SECURITY §4 的本地配置可靠性；实际验证记录由 ROADMAP 汇总。

- 每个 JSON 使用固定的旁路 `.lock` 文件和 OS 排他字节锁。锁覆盖读取当前修订、校验、保护备份及最终替换；同步自动恢复也取得同一锁。锁文件保留，不通过删除它释放锁，避免不同进程锁住不同 inode。进程退出时 OS 释放句柄。另一个写入者持锁时返回 conflict，调用方重读后可重试；不等待无限时间，也不把锁冲突当坏配置。
- 保留现有同进程同路径写队列、baseline 与 expectedRevision；文件锁协调遵守此协议的应用实例，不能阻止外部编辑器忽略 POSIX advisory lock。普通读取不取得写锁；自动恢复前取锁并再次核对原文件。
- JsonFile 支持按版本登记纯转换函数，逐版转换后运行领域校验。缺少 schemaVersion 的历史视为 v1。缺少转换、未来版本及转换失败均不修改原件；转换失败有独立 migrationFailed 结果，不能当损坏文件自动回滚。读时只转换内存数据，首次正常保存才写入目标 schema 并保护旧修订；业务模型按实际变更登记转换，不虚构不存在的历史 schema。
- 启动配置错误页可列出该存储的有效快照，显示时间和修订，并让用户显式选择恢复。快照列表由原存储的领域 validator 校验，界面不直接读写 JSON。未来版本不提供降级恢复入口。
- 显式恢复由 JsonFile 执行，取得同一写锁，验证选择仍属于该配置且内容可用，并检查当前文件未在选择后变化。已有原件（即使损坏）必须先做 flush、读回一致的保护副本，再准备和读回恢复文件，最后替换。失败保留原件；保护失败中止。恢复修订大于当前/所选有效修订，防止旧读者继续提交。不得通过恢复入口初始化空库。
- 成功恢复后由应用使对应 provider 失效并重新跑配置检查；恢复失败仍显示错误页、允许重试，不启动业务流程。

`hosts.json` 现为 schema 2，登记了 1→2 的纯转换（见 HOST_INHERITANCE）；其他业务文件仍是 schema 1，不虚构不存在的历史 schema。不把 Windows 自动测试等同 macOS/Linux 实测。
