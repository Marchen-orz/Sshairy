# 安全、持久化与数据完整性

v0.2。安全不是可选高级功能；M1 起落实适用部分。本项目是本地桌面客户端，不声称可防御已控制当前 OS 用户的恶意程序。

## 1. 数据分类

| 类别 | 保存位置/方式 | 默认进入 AI？ |
|---|---|---|
| 主机、分组、布局、设置 | 应用支持目录的版本化 JSON | 仅授权主机的必要元信息 |
| 密码、私钥、passphrase、API Key | 系统保护的秘密存储；业务对象只放 SecretRef | 不允许 |
| known hosts 公钥与信任记录 | 版本化 trust 数据；可与 OpenSSH 导入互通 | 指纹/状态可以，不能由 AI 批准更换 |
| 终端输出、远程文件、命令 | 内存有界缓冲；默认不录完整终端日志 | 用户明确附加或授权工具读取 |
| 审计、错误日志 | 脱敏且限量；不存原始 headers、凭据或全量参数 | 不自动上传 |
| 外部编辑文件/传输 .part | 私有目录或目标旁暂存文件 | 不自动附加 |

Secret 类型仅帮助避免意外打印，不保证 Dart String 内存擦除、阻止调试器读取或自动防泄漏。缩短秘密寿命，不放 provider 全局快照、异常参数、剪贴板历史或通用序列化。

## 2. 凭据存储

M1 默认每项凭据存系统保护存储，vault 只保存引用。平台插件内部可能使用不同加密机制；先验证实际后端。Linux 无可用 Secret Service/会话未解锁时，允许仅本次连接输入，禁止静默明文保存。

密钥体积或平台限制若需要文件保险库，再以 ADR 引入成熟库的 AEAD 容器：随机主密钥进系统凭据库，每次加密唯一 nonce，明确算法版本、keyId 与认证元数据。不要提前手写 AES-GCM 文件格式或让主密钥直接取自用户短密码。

- 新秘密先写入，成功后提交带引用的 vault 修订；提交失败留下可回收的孤立秘密，不留悬空引用。
- 删除元数据成功后再回收未被任何身份引用的秘密；共享密钥不能随单个主机删除。
- 解密失败是 locked/unreadable，不是空密码，不把密文发给服务器，不覆盖原密文。
- OTP 默认不记忆；私钥 passphrase 与密码的“记住”分别由用户选择。
- 普通日志不打印 SecretRef 对应内容；敏感字段递归过滤，错误诊断 URL 去掉 userinfo/query secrets。

## 3. 主机信任

统一 HostTrustService 服务于直接 SSH、每一跳跳板、SFTP、转发和 AI。

1. 在发送认证凭据前验证服务器密钥与协议签名。
2. 未知端点显示逻辑 hostname、port、路径中哪一跳、算法、SHA256 指纹；允许取消、仅本次信任、保存信任。后台连接遇到未知信任等待用户处理或失败，不自动接受。
3. 同端点同算法密钥改变默认阻断。更换必须用户专属流程展示旧/新指纹；AI 不得通过删除 known host 绕过验证。
4. 新算法但已存在另一算法的可信记录，作为新的待确认密钥，不自动信任，也不错误声称已证明遭攻击。
5. rekey 仍验证，不能用“本连接已确认”接受任意新密钥。协议回调同步/异步约束由 M0 测试。
6. challenge 绑定 attemptId/generation/端点与密钥；旧弹窗、取消后响应无效。超时拒绝。

应用维护自己的 trust 数据，首期不修改用户系统 known_hosts。支持导入普通条目；哈希主机名、通配模式、@cert-authority/@revoked 等须明确支持范围，未支持给出报告，绝不当作“无记录所以可信”。网络地址规范化处理 IPv6、非标准端口；不能把代理的地址当目标端点。

## 4. 配置提交与迁移

目录由 path_provider 等平台 API 决定，不硬编码 OneDrive 或用户目录。建议：vault.json（主机/分组/身份的同一一致性快照）、settings.json、trust.json、workspace.json、transfers.json、backups/、logs/、recovery/。

- 所有配置写入经单写队列；schemaVersion + revision；用 expectedRevision 防并发覆盖。
- 写同文件系统临时文件、flush、验证可读，再使用经过平台验证的替换操作；保留上一已知良好版本。POSIX 目录同步与 Windows 文件占用/替换语义不同，不能把 rename 一词等同跨平台崩溃安全。
- 多个 JSON 分别替换不是事务。需共同一致的主机/身份/分组放同快照；跨秘密存储用上述提交顺序及回收协议。
- 区分 missing/corrupt/unsupportedVersion/permissionDenied/diskFull；损坏或未来版本不能当空库后覆盖。
- 迁移：读旧副本 → 纯转换 → 校验引用与结构 → 保留备份 → 提交新。失败仍能读旧文件。
- 导入先解析成 draft，展示新增/更新/冲突/未支持项，用户提交后一次写入；不是逐条边解析边覆盖。从其他客户端导入时不执行配置中的命令；自动发现只提取元信息，不解码密码。用户选择来源后，适配器在短暂的内存处理中校验 FinalShell 旧式保存密码，预览只保留登录信息状态；迁移默认开启、可关闭。提交时重新读取并解码，经 `HostPasswordImport.importMissing` 写入系统安全存储。原始配置与密码不进入 Host/draft、日志、AI 或明文暂存；预览仅持路径与状态。凭据写入和主机提交在各自串行队列内协调，只补缺失密码；主机提交失败时回收本次新建秘密，回收失败单独报告，不能伪称成功。已有主机只在端点、用户、路由精确匹配且仍使用直接密码认证时补齐，不覆盖现有凭据或认证设置。读 PuTTY/安装信息注册表只用固定参数的 `reg.exe query`（`HOST_IMPORT.md`）。
- 恢复覆盖已有库前，保护备份失败则中止恢复；不能以“备份不是核心”为由继续破坏性覆盖。

本地备份默认保留最近 10 个成功修订（容量上限 50 MiB，设计初值），只备份配置与系统绑定秘密引用，不宣称可跨机器恢复。普通导出默认不含秘密。M5 加密可移植导出需密码 KDF、AEAD、格式版本、导入验证和明确秘密选项；不能把机器绑定密文直接当可移植备份。

当前实现（`foundation/json_file.dart`）：hosts、keys、trust、snippets、settings、forwards 开启快照；workspace、transfers、edits 不开启快照，但传输 checkpoint 与未上传稿仍需要保护，不能把它们当作可任意丢弃的数据。
- 写入：同进程同路径串行；每个 JSON 的固定旁路 `.lock` 使用 OS 非阻塞排他字节锁，覆盖修订检查、备份与替换；进程退出释放句柄，锁文件不删除。锁冲突返回 conflict，不能当坏配置或空库。临时文件写完 flush、读回并经领域 validator 校验后才替换。revision 递增，支持 expectedRevision；旧文件缺 revision 按 0 读，并对照上次读取的文件内容拒绝外部修改造成的覆盖。备份开启时替换前保存旧修订；同一文件 5 分钟内刷新最近快照槽，超出间隔新建槽，每文件保留最近 10 槽，整个目录上限 50 MiB（本文件最新一份不删）。保护备份失败会中止保存。锁协调遵守此协议的应用实例，不能阻止忽略 advisory lock 的外部编辑器；文件比对仍保留。
- 读取：只有 missing 返回 null；corrupt、unsupportedVersion、migrationFailed 与 IO 错误抛类型化错误并锁住普通写入。逐版纯迁移在内存进行，领域校验通过后返回，首次正常保存才保护旧版本并提交目标 schema；缺少迁移、未来版本或迁移失败保留原件。自动恢复要求领域 validator，按最高有效 revision 选择快照；取得同一写锁，先复制损坏原件到 `.corrupt-<时间>-<序号>` 并核对，再验证替换文件和提交。没有有效快照时保留原件并报错，不初始化为空库。
- 恢复入口：启动时 `app/configuration.dart` 检查持久化 provider，失败显示保留文件的错误页、重试和选择有效快照的入口；未来版本不提供降级恢复。显式恢复重新校验所选快照的归属与完整内容，取得写锁，保护当前原件到 `.before-restore-*` 后才提交，修订递增使旧读者失效；失败保留错误页，不启动业务流程。设计和限制见 CONFIG_RECOVERY。
- 2026-11-06 复核发现的三项传输恢复缺陷（保留两者名称判断、源类型重验、任务 ID 路径约束）已修复，并由 `test/files_test.dart` 的回归测试覆盖（2026-11-07 全量 284 项通过）；验证用本机 FileSystem；真实服务器上的续传哈希未验。

## 5. 文件操作可靠性

远程路径采用远端路径语义，不能用 Windows path.join 拼 POSIX SFTP 路径。文件名可含换行、引号、Unicode；不能拼 shell 做通用浏览/删除。上传/下载路径与资源身份明确绑定，未知 stat 错误不是 ENOENT。

- 上传写目标目录旁唯一 .part；下载写目标同卷 .part。检查大小后发布。大小校验只检测长度异常，不证明内容相同；测试使用哈希确认。
- 服务器若有 POSIX rename 扩展可提供原子替换；普通 SFTP rename 不保证覆盖语义。无法安全替换时保留原文件，提示用户选择，不能先删原件再伪称“原子覆盖”。
- 覆盖前重新读取目标身份；本地排他创建防目标抢占。远端 SFTP 缺少通用 compare-and-swap，必须说明检查与提交之间仍有竞态窗口。
- 默认不跟随符号链接递归；删除 symlink 删除链接本身。覆盖链接显式询问“替换链接/取消”，不静默修改链接目标。
- 目录递归有深度/条目上限、循环检测；取消不发布半文件。目标预留锁避免两个任务同时写同一路径。
- 保存外部编辑稿前比较远端基线；变化则进入冲突状态。可对小文本用内容哈希辅助，不保证 size+mtime 能发现全部修改。
- 不能无条件规范化 CRLF、编码或权限；用户没选择转换就保持原字节。

## 6. AI 的不可委派权限

AI 不可读取原始秘密、扩大自身授权主机范围、改变审批策略、关闭审计/信任验证、导出秘密、自动接受服务器换钥、修改模型端点或安全存储配置。普通 theme/font 等设置可授予能力；设置不是统一 low risk。

任意 shell、远程文件内容、主机标签和工具输出都可能含不可信指令。模型输出必须经过确定性的范围和参数校验。任意 shell 无法靠关键词判断“只读”；危险命令规则只是告警，不是安全沙箱。详见 AI.md。

服务器监控（MODULES §8）只执行代码里的常量只读命令，不拼接主机名、路径或任何输入；它取用已通过主机校验的连接，遇到主机密钥或口令询问一律拒绝。监控数据只显示，不写日志、不发给 AI。

## 7. 日志与临时数据

默认诊断日志上限 5×2 MiB，审计保留 30 天且总量不超过 20 MiB（设计初值）；只记录元信息。启用终端录制必须显示状态、按会话控制、限制容量，并提示可能含秘密。

外部编辑临时目录权限仅当前用户；完成后有界重试清理，Windows 文件锁时记录待清理项。未成功上传的稿件保留到恢复中心，不为清理整洁丢弃用户数据。AI 对话持久化默认只存脱敏文本；完整工具输出若需落盘必须加密或采用显式授权的短期私有文件，设置 TTL 与大小上限。
