# 诊断日志（一期）

按 SECURITY §1/§7 落实本地、有界的诊断记录。日志不自动上传；M4 能力调用审计另行实现，诊断日志不能冒充审计。

- 只接受枚举形式的区域、操作和结果，以及整数耗时；记录 UTC 时间。接口不接受自由文本、异常对象、堆栈、终端输出、命令、路径、地址、URL、主机标签、SecretRef 或请求参数。通过结构限制避免依赖关键词过滤来保护秘密。
- 主程序在应用支持目录的 `logs/` 中初始化；连接拨号、传输终态及未处理的 Flutter/异步错误只写上述元信息。不修改错误的业务语义，不把编程错误映射为网络成功。
- 最多 5 个文件，每个 2 MiB（含当前文件）；单写队列轮转。等待写入的记录最多 256 条，超出时只累计丢弃数量，写入下一条时记录数字。错误洪水不形成无界内存队列。
- 诊断写入失败关闭本次进程的记录器，保留既有日志，不引发递归异常或阻断连接/配置/退出。`idle` 可供退出等待待写记录，日志失败不冒充业务保存失败。
- 不保留原始堆栈意味着当前只能定位区域、操作和时序；后续若需更详细的堆栈，必须先设计不包含源路径/异常消息的安全投影。此轮不启用终端录制，也不增加导出到外部服务的入口。

自动验证：轮转容量、排队上限、枚举投影、写入失败不影响调用。真实服务器操作与秘密扫描结果另记 ROADMAP，不能由单元测试推定。
