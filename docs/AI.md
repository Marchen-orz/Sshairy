# AI 设计（M4）

v0.5 · 2026-11-11。本文定义目标与实施契约，功能完成与否只看 [ROADMAP](ROADMAP.md)，实际验证只看 [TESTING](TESTING.md)。现有补全说明在线翻译不等于 AI 助手已经接入。

## 1. 产品方向与范围

完整目标是 SSH 专用 Agent，并提供三种分工清楚的 AI 入口：**侧边栏 Agent 助手、行内命令生成、AI 提示补全**。Agent 拥有最完整的业务工具，可在用户授权下管理软件与多台服务器；行内生成和补全都是无工具的短请求，不能继承 Agent 的执行权限。三者共享模型接入、上下文投影、取消与资源预算，不做三个相互独立的 Agent。

用户不必复制多段输出到网页，也能看清 AI 查过什么、改过什么、还缺什么依据。证据引用、多机确定性比较与变更后验继续作为 Agent 的特色；行内生成追求明确触发和快速回填，补全追求意图清楚时才建议、不为凑候选而硬补。自动识别只产生本地提示；行内请求要点击/快捷键，自动补全在功能开启且输入满足条件时请求。两项功能默认值及主机筛选见 §4.3/4.4。

完整目标分步实现，不把“首个单机诊断可用版”当作完成整个 Agent。先打通共用底座与两个轻量入口，再交付 Agent 执行/诊断，最后收齐应用管理、多机任务、文件写入、传输、转发和受管长任务。先服务作者的 Ubuntu；其他系统按探测结果明确 unsupported，不自动套 Linux 命令。

AI 未配置或关闭时，SSH、文件、监控和设置完整独立；启动不探测模型地址、不请求模型、不上传遥测。无 Node/Python 常驻运行时、MCP、外部 CLI Agent、浏览器、插件市场、子 Agent 编排或本地模型捆绑。直连 HTTP 的内存收益须实测。

### 1.1 三种入口

| 入口 | 任务与触发 | 上下文 | 工具与结果 |
|---|---|---|---|
| 侧边栏 Agent 助手 | 用户发送目标，持续规划、查证、执行、验证；复杂任务可覆盖多台已授权服务器 | 发送时的聚焦 SSH 主机；无聚焦时根据用户对话从已保存主机快照确定目标；附件、已授权结果、对话与任务记录 | 最完整的 Capability 子集；每次调用仍受 scope/审批约束；产出执行记录、证据和验证结果 |
| 行内命令生成 | 本地识别非命令意图，在当前 pane 右上角亮 AI 图标；点击或 Alt+Enter 后生成 | 固定当前终端身份、已知系统/shell/cwd、本次自然语言与有限同会话命令历史；原始输出不自动附加 | 无业务工具，无远端探测，不执行；终端内加载后返回一条命令草稿，复杂/含糊则澄清或建议转 Agent |
| AI 提示补全 | 输入已有足够信息，停顿后按功能设置请求；意图不清就不补 | 当前终端命令前缀、已知环境与有限同会话近期历史投影 | 无工具；最多一个高质量、可纯追加的候选，位于候选框第一项；Tab/点击接受，不附回车 |

“最强”指业务能力范围最大，不等于能读秘密、改自身授权或跳过主机信任。三个入口共用用户选定协议/endpoint，可分别指定同端点的模型，也可选同一个型号；不自动切换更便宜的供应商。切换入口不自动传递对话、历史、批准或多主机范围。

### 1.2 Agent 功能与完整目标

| 功能 | 用户得到什么 | 交互与实现 | 阶段 |
|---|---|---|---|
| 对话与选区解释 | 解释错误、日志、命令及退出状态 | 终端选区/粘贴文本作为可删除附件；默认不附整个回滚，不读取其他标签 | M4a |
| 三入口共用模型底座 | 选择模型/目的地，独立开启生成与补全 | 配置档、窄凭据端口、协议/取消/投影；行内与补全交互见 §4 | M4a |
| 单机诊断 | 排查负载、内存、磁盘、服务异常，指出下一步 | 固定采集器先取得结构化事实；不足时提出有依据的命令请求 | M4b |
| 可见执行 | 看见目标、cwd、命令、双流输出、耗时与退出码 | 独立 SSH exec，唯一 Stop，结果与发送范围可检查 | M4b |
| 文件与日志分析 | 分析指定小文本，不把整盘递归发送 | SFTP list/stat/read 的受限端口；指定文件/范围，发送前预览，二进制拒绝 | M4b |
| 应用控制 | 调整主题/字号、分屏/焦点，打开已授权主机 | 已有 typed 用例经 CapabilityDispatcher；普通设置可撤销，创建/关闭 shell 单独处理 | M4c |
| 多主机比较 | 同一检查在数台主机上对照，定位异常节点 | 固定主机集合、同版本采集模板、本地规范化比较、模型解释差异 | M4c |
| 变更验证 | 改动前看基线、改后看预设检查，区分执行成功与修复成功 | 变更方案绑定目标/前置条件/验证项；首版由批准的 shell 完成变更 | M4c |
| 对话与交接 | 历史、引用、未完成项、可审阅的交接材料 | 有界脱敏历史；导出是用户操作，预览后保存，不自动上传 | M4c |
| 主机/工作区管理 | 建立非秘密主机草稿、调整分组、打开/关闭授权会话与布局 | 复用 typed 用例，精确对象/引用/修订验证；认证与信任交给用户 | M4d |
| 远程文件与传输 | 修改配置、管理指定目录、上传/下载及跟踪任务 | diff/基线/安全发布；类型化 SFTP 操作与传输 ID，选择过的本地文件授权，不提供任意本机磁盘工具 | M4d |
| 转发与长任务 | 创建受限转发、运行可停止/可查询的有限长任务 | 明确源/目的端与绑定地址，任务 ID/所有者/输出分页/TTL/终态；不开放无人值守调度 | M4d |
| 排查流程 | 把一次有效排查变成下次可重跑的检查表 | 固定诊断模板与类型化参数；不把聊天记录当可执行脚本 | M4d |

M4a–M4d 是实现顺序，详见 §13，不是独立模块。M4a 包含三入口的配置/生成底座，M4b 是可执行 Agent 的首个可用里程碑，M4c 收齐诊断特色，M4d 收齐上述完整 Agent 业务工具。不能因 M4b 可用而勾选完整目标；专用可见 PTY、定时无人值守仍非本设计范围；本窗口权限模式见 §4.1。

### 1.3 典型任务

- “这段报错什么意思”：只发送用户选区，解释依据与缺少的上下文；不拨号、不执行。
- “这台服务器为什么卡”：冻结当前聚焦 SSH 主机；无聚焦目标时先确定用户所指主机 → 选择固定诊断模板、采集必要指标 → 结论引用采样 → 如需日志/命令再请求授权。
- “这三台只有一台接口超时”：用户选择三个 HostId → 比较同一模板 → 展示数据缺失、差异和待验证假设，不自动重启异常节点。
- “把当前主机左右分屏，字号改为 16”：在提交时固化当前目标，走工作区和设置用例。字号可按修订撤销；分屏会创建新 shell，不能把关闭该 shell 当无风险撤销。
- “按这个方案改完检查”：先固定检查项，执行获批命令，再采集同口径结果；退出码 0 仍可能显示“验证未通过”。
- 在当前终端输入“查看占用 8080 端口的进程”：本地显示 AI 图标 → 点击/快捷键 → 原位加载 → 生成适合当前已知系统的命令草稿 → 用户确认后自行 Enter。
- 输入 `docker logs --tail 100 `，近期同会话明确操作过一个容器：功能开启且意图足够明确时，候选框首项给出该命令的可追加部分；存在多个同样合理的容器则不出 AI 项。候选不证明容器仍存在，也不自行枚举容器。

## 2. Netcatty 参考与差异定位

证据统一在 [NETCATTY_REVIEW](NETCATTY_REVIEW.md)。固定版本 `0e3f282657df29a5dc6939c86dbf4ea3ad2be8ea` 已能多步调用工具、审批、停止、管理上下文并通过可见 PTY 执行；“会聊天、能执行命令、能控制软件”不能作为 sshairy 独有卖点。

| 参考版已有 | sshairy 拟做的具体区别 |
|---|---|
| README 已展示多主机编排与跨机部署 | 同版本采集器 + 本地确定性差异表 + 时间偏差/缺失字段提示；不把“能操作多台机器”当区别 |
| prompt/runtime 已有多步计划；终端 artifact 已含来源和行范围 | 客户端验证的跨工具 Evidence 引用，区分采集事实、推测与缺口；不声称参考版没有引用或计划 |
| snippets 与 JavaScript automation scripts 可复用，还可设置触发条件 | 受类型约束、固定采集器与断言的诊断流程；首版不执行导入脚本，不声称上游无法做 runbook |
| write/mode 审批、权限规则和结果去重 | 目标/参数/scope revision/配置与连接代次绑定，持久 intent 和 outcomeUnknown；所查路径未见同等完整协议，不扩大为产品绝对缺失 |
| 短命令/长任务、SFTP 写入、主机/转发控制 | 完整 Agent 也覆盖这些业务；按阶段逐项开放，区别在精确授权、证据和变更后验，不以延后功能包装成特色 |

借鉴单轮互斥、统一 Stop、工具卡片、输出句柄和上下文预算。独立实现调度与 UI，不复制 GPL 工具目录、prompt、代码或素材。首版选独立 exec，技术理由见 [DESIGN ADR-06](DESIGN.md)。

差异以完整工作流定义，不能由“模型理论上能做”替代产品能力，也不能由“参考版本未见”推出 Netcatty 最新版做不到。§3 的能力是本项目拟实现方向；没有完整上游证据的项目按未核实处理。

## 3. 值得优先做的特色

### 3.1 结论可追溯的诊断

**价值**：用户能点开“磁盘空间不足”的真实依据，区分事实、推测与待检查项。

每次采集生成不可变 Evidence：evidenceId、HostId、连接 generation、collector/version 或 executionId、客户端采集起止时间、字段/行范围、脱敏内容摘要、截断状态、授权来源。模型只得到已经允许发送的投影和短引用 ID，不得到本地凭据引用。

回答中的引用由客户端解析并核对实际 Evidence；不存在、无权限或已失效的引用不渲染为已验证。事实字段的数值来自结构化数据，模型解释只是注释。证据支持某条输出确实存在，不证明模型的因果判断正确；未引用的结论显示为分析文本，不伪装成检查结果。

示例：`/var 可用空间 2.1% [E7]；与本次服务失败的因果关系尚未证实，下一步检查指定时间段日志。` 点击 E7 打开当次值及采样时间。CPU/网速用两次样本，单次值不伪造利用率；旧证据在重连后只能作为历史资料。

**实现与成本**：Evidence 是工具结果的投影和索引，复用 OutputStore，不复制终端全量缓存；本地解析引用，无需向量数据库。M4b 先做行/字段引用，后续再考虑可折叠的“假设 → 检查 → 结论”列表，不先做复杂图编辑器。

### 3.2 多主机差异诊断

**价值**：同配置集群里“只有一台不正常”时，先定位差异，减少逐台复制输出。

用户固定最多 5 台主机和一个基准节点，选择同一诊断模板；全局最多 3 个采集任务并行。每台返回独立成功/失败，不因部分成功填补缺失值。客户端先统一单位、字段与排序，计算版本、容量、状态差异，模型只解释必要差异并提出下一步。

第一批比较系统/内核版本、uptime、负载、内存与挂载容量；后续加明确选择的服务状态和配置内容哈希。含 IP、用户名、挂载路径的字段需数据范围授权；默认主机别名替代完整连接地址。不发送进程完整命令行、环境变量或全量日志。内容哈希也需要获准读取文件，不能用“只发哈希”绕过敏感文件策略。

采集记录客户端起止时间、样本间隔和失败原因；不声称跨机原子快照。CPU 架构、角色、配置版本不同会影响可比性，界面直接显示；只有相同模板和可比较字段才进入确定性差异表，异常原因仍是待验证解释。

**实现与成本**：复用同一 Collector 与连接租约，新增纯 Dart 规范化/比较函数和表格。无服务端 agent、无子 Agent、无自动批量写入。M4c，成本中。

### 3.3 先约定验证，再做变更

**价值**：避免“命令退出 0，AI 就宣布修好了”。

变更方案包含目标、当前基线、精确动作、预期效果、前置条件、验证检查、停止条件及可选补偿。用户批准的是具体动作；模型写在计划里的文字没有授权效力。验证项在变更前固定，改动验证标准需要用户确认。

执行前重验主机路由/修订、连接代次和必要基线。变更后使用同口径模板比较；结果分为未执行、执行失败、结果未知、执行完成但验证失败、验证通过。对没有确定性判据的项保留“需人工确认”，不把自然语言自评作为自动验收。

首版支持普通设置与获批 shell 的前后对照；shell 没有通用撤销。补偿也是新动作，需要新的批准。后续远程文件修改使用小文本 diff、编码保持、原件保护、目标旁暂存、提交前重读、验证失败保留恢复材料；检查与 rename 之间的 SFTP 竞态须如实保留。

**实现与成本**：复用 OperationId、Evidence、revision/基线检查，增加轻量 ChangePlan 与 VerificationResult；不先做 DAG 工作流引擎。M4c，成本中；文件事务成本高，单独验收。

### 3.4 可保存的排查流程

**价值**：把“上次怎么查好的”保存成可重复检查，而不是每次重新教模型。

有效诊断结束后，AI 可提出流程草稿：名称、适用系统、参数定义、固定采集模板、顺序、确定性断言、人工判断项和版本。用户审阅后保存。首批仅允许诊断模板，参数为 HostId 列表、受限服务名等类型化值；不允许任意脚本、eval、模型生成的表达式或嵌入凭据。

重跑时重新选主机/授权/基线，旧批准不继承。步骤顺序执行、独立采集最多 3 并行，不支持任意分支循环。校验失败立即标记该步，最后输出同一格式的报告。保存入口是普通 typed 用例，用户数据文件不是新的可执行插件机制。

**实现与成本**：版本化 JSON、小型顺序执行器、现有 Collector 与断言枚举；不引入通用 DSL。M4d，成本中；确实反复使用后再扩展变更流程。

### 3.5 数据发送可见、成本可见

**价值**：用户能知道“AI 看到了哪些服务器数据、这次还有多少工作”，尤其适合自定义云端或本机模型。

输入框显示只读目标、附件和模型目的地；请求详情展示按来源归类的字段、截断/脱敏量、工具 schema 与估算 token。发送过的数据按本地记录列出，但撤销本地附件不能撤回供应商已经收到的数据。原始终端/文件/命令输出默认本地预览后选择发送。

模板检查先在本地解析、比较和过滤，再发送小结果；不让模型看整个进程表后再自行过滤。展示实际 usage，缺 usage 就标未知；金额只有配置了有效单价才估算，不把 token 估算当账单或硬金额上限。

**实现与成本**：复用安全投影、ContextManager 和 usage 事件，不另建数据代理。M4a 开始，M4c 补完整请求来源明细，成本低至中。

## 4. 界面与任务交互

### 4.1 侧边栏 Agent 助手

视觉布局权威规范见 [UI](UI.md)。侧边栏是完整 Agent 的入口，在终端右侧与文件互斥显示，不叠两个完整侧栏；也可从主机库/命令面板打开无终端附属的任务。宽窗可拖宽；不足最小终端宽度时用覆盖层。关闭面板只收起，任务继续；活动任务以按钮状态显示，点击可返回，用户不必保持面板可见。

面板从上到下：紧凑的 Airy 标题与新建/历史/设置、消息与工具卡、输入框。回复渲染 Markdown，支持段落、列表、引用、行内代码与代码块；代码保持可选/复制，不执行 HTML、脚本、远程图片或自动请求外部资源，链接经现有用户外链动作处理。用户消息使用紧凑边框气泡，助手回复下方提供复制/重新生成/撤回操作。输入区以贯穿分割线分隔，直接使用无额外外框和着色背景的多行 composer，生成中仅在消息左下显示加载点，不在顶栏显示已完成状态，下方工具栏包含当前模型、上下文估算占用圆环与权限模式，控件等距居中、模型弹性占宽，发送/Stop 为右下角的 28 px 圆角方形；窄栏或大字号分两行。只读主机名以次要半透明文字显示在顶部 Airy 标题与工具按钮之间，不额外占一行，不放主机选择器；模型下拉与设置共用选择器，在用户打开或刷新时获取目录，搜索已取得的 ID，不依赖共享目录缓存。当前模型是全局最后选择：同一协议与 endpoint 下记住并跨重启沿用，目的地改变时回到该配置的默认模型，不按历史会话保存，也不改写配置默认。Enter 发送、Shift+Enter 换行，IME composing 时不发送。设置中的模型能力与上下文/输出限制直接展开，未知能力不以推测当保证；聊天不放常驻教程或重复标题。选区菜单和命令面板只通过明确“询问 AI”动作打开，搜索无结果不自动发送。

| 组件 | 内容和行为 |
|---|---|
| 目标 | 发送时冻结工作区聚焦的 SSH 主机；没有聚焦主机时可查询已保存主机 ID/别名，根据用户目标确定一台，未指明或有歧义则反问，不按列表顺序猜测。一次 turn 首个有效 HostId 在拨号前锁定，连接失败也不得改猜另一台 |
| 自主步骤 | 统一 Agent，没有解释/诊断/执行工作流或主机下拉；权限模式为观察/确认/自动，每个新会话重置为确认，仅窗口内保留且每 turn 冻结。观察仅开放主机列表、固定只读诊断和已共享输出，确定性拒绝任意 shell；确认对每条任意命令审批；自动允许本次固定目标上的任意命令免逐条审批。模式由用户 typed 用例改变，运行中禁改、历史不恢复，不可委派权限、主机信任、目标绑定、intent、Stop 和输出发送确认始终保留。服务不支持工具协议时明确失败 |
| 附件 | 显示来源、时间、行数/字节与截断，可预览、裁剪、删除；不静默附全屏/剪贴板/其他标签 |
| 计划 | 简短步骤和已完成/待办；模型文字不能伪造执行状态，状态以客户端事件为准 |
| 审批卡 | 固定目标、账号、cwd、完整命令/变更、发送范围、超时；允许一次、拒绝、编辑后重新审批；普通可逆设置可授本对话权限 |
| 输出卡 | stdout/stderr 独立、有时间/退出码/截断；展开有界分页，输出是纯文本，剥离终端控制序列，不执行链接/ANSI/HTML |
| 证据与比较 | 引用跳到字段/行，比较表来自客户端；过期/缺失证据明确显示 |
| 变更与验证 | 动作结果与检查结果分别显示；不把用户拒绝、取消、未知写成完成 |
| Stop | 运行中替代发送按钮；统一取消所有本 turn 工作，收束状态见 §8 |

侧栏助手的用户可见名称为 Airy，内部 Agent 类型/工具 ID 保持不变。顶部历史入口在侧栏标题下原位向下展开有界可滚动列表，不创建弹出层，展示按更新时间排序的本地会话，可新建、查看、切换和删除；运行中可以查看列表，新建、切换和删除均须先停止或等待任务结束，不隐式取消任务。每会话保留本地草稿，目标在每次发送时按当前聚焦主机解析，未发送草稿仅内存；关闭侧栏不丢草稿。历史仅保存有限用户/助手文本、执行状态摘要和用户已允许发送的输出投影，不保存执行卡中的命令全文、目标账号/地址/cwd、原始双流、批准/句柄/租约或 provider 私有续接。用户/助手文字本身仍可能含业务信息、命令或地址；已知秘密形态仅作辅助脱敏，不承诺识别任意秘密。用户可删除会话；容量与保留期限只在 §9 定义，按完整旧 turn 裁剪并显示标记，最新 turn 单独超限则拒绝保存而不截短文字。坏档/未来版本保留原件并阻止普通写入，读取或保存失败保留内存并给出重试入口，不初始化空库覆盖。

会话切换/重启恢复只恢复可读历史，不恢复工具批准、输出发送权和执行。用户发送下一条即表示继续当前会话，无逐轮确认弹窗；发送前仍重验原模型目的地、HostId、完整有效路由及当前信任/SSH 凭据修订的指纹。绑定不匹配时不发送旧历史，原位提示并提供新会话动作，草稿保留，不弹出重复确认。路由配置不落盘，只保存不可逆指纹；信任/凭据修订目前是进程内计数，指纹另绑定本次运行 nonce，因此重启后的主机会话只能查看，再发送须新建会话；无主机文字会话可在目的地匹配时直接继续。继续时每 turn 仍使用新的 owner、审批和供应商协议上下文，将 §9 限额内的历史作为普通数据块送入，不重建旧 tool call/result 或 opaque，不复活旧输出 handle。无聚焦主机的发现模式不自动续传已绑定其他主机的历史；本次首次实际选定主机后，记录绑定该主机及发送时的路由指纹。单实例 AgentRuntime 保持应用唯一工具授权身份，历史切换不会销毁活动执行所有者。

回复提供复制、重新生成和撤回上一轮。重新生成是新的无工具回答请求，只用当前绑定下允许续传的有限文本及已共享投影，不重放 SSH、固定诊断、旧批准或私有输出；失败保留原回答与草稿。撤回只调整对话上下文并恢复该轮用户草稿，不撤销远端操作；执行摘要保留可查，不能由撤回抹去执行记录。忙时禁止重生成/撤回，草稿已有内容时不得静默覆盖。复制只写用户显式选择的可见回复文本。操作不扩大历史目的地/主机绑定，也不恢复旧权限。

答复应直接说明结果和必要缺口，不强制每轮附“证据在哪”或裸任务编号。客户端仅将当前会话已存在的 execution/operation ID 渲染为可点击的本地执行记录引用，点击定位并展开相应执行卡，不执行命令、不拨号、不打开任意外部链接；不存在的 ID 仍为普通文本，恢复记录没有原始输出时如实显示不可用。此能力只定位执行记录，不代表已实现 §3.1 的字段/行级 Evidence。

忙时输入保留为本地草稿，用户停止后或结束后再发送，不自动排队；收起重开保留输入和当前输出发送编辑；活动任务的目标保持发送时的绑定。消息与工具执行按实际时间顺序排列，当前待处理审批/发送选择始终可达；未配置与空闲使用专属品牌 pose 和短动作入口，开始任务后让内容占主导。对话/输出列表虚拟化，文字增量约 50ms 合并，历史 Markdown 不每字符重排。草稿与快捷键尊重 IME；Esc 收起面板，不隐式停止远端操作。用户可见文案全部 zh/en。

### 4.2 行内命令生成

目标是“一句需求，一条可编辑命令”，请求只服务当前终端，不启动 Agent 循环。体验：`输入需求 → pane 右上角 AI 图标 → 点击/Alt+Enter → 自动生成 → 命令预览/草稿 → 确认只插入 → 用户自行 Enter`；有草稿时打开即生成，不再需要先填指令再点生成。自动的是意图提示；发送模型是用户明确动作。复杂任务、缺少必要参数时返回澄清或“转 Agent”入口，转交须用户点击；发送 Airy 目标时按 §4.1 冻结聚焦主机或进入发现流程，不在后台扩大范围。

**本地识别。** 只在焦点 pane 的普通可编辑单行提示符、光标行尾、已回显且无在途输入、IME 已提交时判断，输出 `command / naturalLanguage / uncertain`。按语言问句/请求结构、命令词与参数结构等多信号保守组合，不把中文、空格、无静态规格或未知首词单独当作自然语言。别名、函数、中文路径/参数、`echo 查看磁盘` 保持命令；不确定不点亮，图标与快捷键仍可显式打开生成预览。识别器不联网、不拦 Enter、不改变历史/远端输入，也不靠每键请求 LLM 分类。

**上下文。** 点击时固化 TerminalContext：HostId、SessionId、shell/transport generation、draftRevision、本次输入、光标、已知 OS/shell/cwd 及各字段来源/新鲜度、profile/destination revision、功能配置与主机可用性修订。功能启用即包含当前需求、必要的已知系统/shell/cwd 与有限同会话命令历史，无独立历史许可；用户名/完整地址、原始输出不自动附加。未知 cwd 省略，不因未开 SFTP 或没有 OSC7 而阻断生成/补全；不增加后台探测。未知 cwd 不伪装 home，未知系统请求澄清；tmux/su/sudo -i/嵌套 ssh 的内层身份未经验证时不可称为“当前服务器”，降级为手动确认目标或只展示生成预览，不自动回填。不为补上下文自动执行探测或 SFTP 查询。

**请求与结果。** 无 tools，单次输出受限 `status=command/clarify/useAgent`、command、简短说明/问题及必要假设；只收合法完成的结构化结果，不从任意 Markdown 中抓第一段当命令。command 允许一个短 shell 逻辑行，必要管道/引号由目标 shell 语义校验；不允许换行、NUL、ESC/终端控制序列、双向隐藏控制符或多命令脚本。结构/语法校验不能证明语义安全；不从错误输出修补成可执行命令。用户看完整命令后决定提交，永不生成完成即执行。

**输入所有权与回填。** 当前 SSH 是按键实时发远端，检测到的自然语言很可能已经处于远端编辑缓冲。OSC 输入边界也不等于 shell 提供原子整行替换。两种路径必须区分：

- 默认路径：识别已经回显的需求，生成结果显示为当前输入行附近的本地可编辑预览。原文不被 AI 改写，不发送 Ctrl-U/Ctrl-C/退格/方向键清行。用户可复制，或自己清空原行后点击“填入”；点击“填入”是新的用户接受动作：保持原目标/环境，绑定此时空行的新 revision，不复用生成时非空草稿的 revision；窄 typed 端口重新检查空提示符、连接代次、实际回显、光标/输入 revision、无未回显输入、IME/屏幕模式，再只粘贴完整命令而不发 Enter。无法证明空行就保留预览，禁止自动追加到自然语言之后。
- 无缝路径：在空且可识别的提示符由快捷键/菜单显式进入本地行内输入层，需求、生成动画与命令编辑全在本地，不发送原文。生成后直接替换本地草稿；用户点击/Tab/结果态 Enter 接受才经同一空行检查把命令写入远端，之后再按 Enter 执行。普通终端输入仍实时发送，不能中文打到一半才静默改为本地模式，也不把所有 shell 行编辑搬到客户端。

本地层状态归 terminal/application，模型只有生成文本权限；用户接受是 UI typed 输入，不登记 `terminal.write`、不向 Agent 暴露逐键/删行工具。生成过程中显示本地 overlay/spinner，不写 ANSI 动画、假提示符或日志到远端/xterm 回滚，也不挡住远端真实输出。

**失效与取消。** 输入所有权以当前 pane 及其自有 AI 图标/预览/本地输入层为整体，点击这些控件不因 Flutter 焦点变化误取消；转到别的 pane/标签/应用输入区域才算失焦。新输入/回显改变草稿、焦点切换、cwd/身份变化、断线/重连、IME 开始、模型目的地/授权变化均取消旧请求并使结果不能自动回填；已经本地显示的预览可保留并标目标变化，仅允许重新核对/复制。Esc/取消按钮只停本次生成，错误保留原文并手动重试，不改用另一个供应商。默认终端中 Enter 始终提交当前真实行，不因识别切成发送 AI；只有显式本地输入层内 Enter 才按该层的生成/接受规则处理。

### 4.3 AI 提示补全

与本地历史/静态规格/路径补全并列为独立来源，纯规格引擎不调用模型。是否可请求由 AI 总开关、补全功能开关和当前主机可用性共同决定，默认值与高级设置统一见 §4.4；主机筛选只控制该功能，不改变 Agent 工具范围。

**何时请求。** 本地先确认可编辑提示符、行尾、无 IME/在途回显、支持的简单 shell 上下文；排除密码/交互提示、备用屏幕、命令运行、自然语言和不可靠内层身份。命令名已明确，并已有子命令/选项/部分参数等有效信息时才进入候选；`d`、`git ` 等过短/分支众多输入不请求。已知等待秘密的参数、前导空格、不完整秘密标记等也跳过。空格数量/字符数不是意图清楚的充分条件。

**如何用历史。** 功能开启时，只用同 SessionId/shell generation 的近期本地记录，按相关命令/当前上下文筛选，并按时间排序。M4 将本地历史从纯字符串补为带提交时间、shell generation/身份来源的记录；重连/身份变化清空 AI 可用投影，无来源的旧条目只用于本地历史，不把请求上的新 generation 当作历史条目来源；不读 `.bash_history`/远端文件，不附 Agent 对话、其他 pane/主机、完整回滚或路径目录缓存。历史条数/字节预算见 §9。只发送非秘密、有明确必要性的投影；混有疑似秘密的条目整条排除，不能为脱敏扫描凭据库。无近期记录或多个目标同样合理时允许 abstain，不能猜分支/容器/文件存在。输入本身已有的路径可以按授权随草稿发送，目录提供器读到但用户没输入的名字仍不发送。

**何时展示。** 模型返回 `suggest/abstain` 与最多一个完整候选；可带自评确定度，但不作为校准概率或授权依据，不设置“confidence > 0.8 就可信”的伪保证。客户端还需确认：目标/草稿/上下文不变，候选严格以已回显原草稿为前缀、有非空后缀、目标 shell 上下文兼容、无控制/隐藏字符、符合长度与单行限制，不改写已输入词或插入回车。实体参数（容器/分支/路径等）须有当前草稿或筛选后的近期历史依据，固定命令/选项可对照已有静态规格；无依据的具体名字不展示。语法匹配不等于意图匹配，模型仍应主动 abstain。不合格、错误、低确定性或解释性文本直接不显示 AI 项，不重问模型凑答案。

高质量项排序为 **有效 AI → 本会话历史 → 规格/路径/片段等**，按完整插入文本去重；若与历史相同只显示一个，以 AI 首项标记并保留可查看的来源。其他来源仍按既有规则显示，AI 无结果时无空占位/错误 toast。迟到 AI 可进入第一行，但不能抢走已经存在的选中对象；用户正在导航/悬停时不换选择，原对象消失须重新选择，避免 Tab 突然接受另一条。

**失效。** 新输入/提交、失焦/切标签、IME composing 开始、提示符/备用屏幕/命令运行状态变化、重连/身份/cwd 变化、历史清空及授权/目的地变更，都取消补全 HTTP、撤销候选/需求并失效相应缓存。回包、缓存命中、显示和接受前均重验当前 eligible 状态及全部修订，迟到结果不得重新打开已关闭候选；同一草稿也不能跳过检查。

**接受与退出。** Tab/点击只追加验证过的后缀，复用 generation/revision/实际回显检查，不执行也不额外发换行。AI 整句候选不机械再加空格，目录/普通规格仍沿用自身规则。Enter 保持提交真实已输入命令，不隐式接受首行 AI；Esc 取消本草稿 AI 请求/候选，Ctrl/Cmd+Space 可重新打开候选，但只有已启用 AI 自动补全才可能发模型，不是新的发送授权。用户继续输入立即取消旧请求，不追着每个键补。

### 4.4 三入口的设置与调度

设置集中在现有设置弹窗内，按实际配置顺序排列：协议（新配置默认 OpenAI-compatible Chat Completions）→ endpoint → 可选 API Key → 获取并搜索模型列表 → 默认 Agent 模型、行内生成模型、AI 补全模型。三类模型独立保存，可选择同一个模型；修改聊天输入区的当前模型会作为全局最后选择持久化，同一协议与 endpoint 下重启继续沿用，不改设置默认；已保存默认 profile 的目的地变化时重置当前选择。模型列表仅在用户明确打开选择器或获取/刷新时，以所选协议的 `GET <endpoint>/models` 请求目录，不在启动、输入 Key 或编辑地址时自动探测；失败保留已有选择并允许重试，服务没有模型目录时仍可填写明确模型 ID。Key 可空以支持无需认证的合法 endpoint，非空仍只存系统安全存储。Agent 不再提供“工具开关”：聚焦或发现模式始终向模型提供当前受审工具目录，主机范围由 §4.1 的发送快照与单目标锁定约束；具体工具执行仍经本地 schema/授权/审批与重验，模型能力未知不能跳过这些检查。上下文窗口默认 1M tokens，提供 256K 预设与自定义值；最大输出默认 4096 tokens，可配置值须经范围验证。能力、已选上下文与最大输出限制始终显示；当前模型目录仅返回 ID，不提供能力或窗口元数据，能力标未知，不自动声称服务支持工具或指定窗口。AI 总开关默认关闭，行内生成和自动补全的独立开关默认开启；分别按点击动作或满足条件的输入触发。每个开启的功能各有默认折叠的高级设置，仅配置默认全选的可用主机；取消勾选关闭对应主机的该功能，持久化为默认空的 HostId 排除集合，新增主机默认可用。功能启用即包含所需输入、已知环境与 §9 限定的同会话命令历史，不再设置历史开关、逐主机发送许可或 Linux/POSIX 确认，也不依赖旧 terminalDestination 字段。配置 schema 1 升级到 2 时一次性将两项功能设为开启，因为旧档的 false 无法区分旧默认值与用户选择；schema 2 保留用户明确保存的关闭状态。模型、endpoint 或路由变化不重置功能开关和主机排除项，但取消受影响请求，并按新目的地、配置和连接身份重新校验。本地行内生成按已知 shell 类型处理；未知 cwd 可省略，不主动探测补齐。可靠提示符、回显、IME、代次与秘密过滤仍须满足 §4.2/4.3；提示符识别不证明 tmux/su/嵌套 ssh 的内层身份。目的地、自动触发开关与主机可用性都是用户专属，Agent 的 settings.patch 无权读改；普通外观设置仍按白名单开放。

采用共用请求调度：Agent 最多一个活动 turn，行内生成与自动补全属于独立可取消短请求，不占成 Agent 对话。显式行内请求优先于自动补全，取消被取代的补全；Agent 可继续自身执行/采集，不为抢模型额度重复工具或取消远端命令。全局网络并发、延迟、限频与超时只在 §9 定义。无工具模型可以服务行内/补全和文本解释，不能因此开启可执行 Agent。

## 5. 模块与已有能力的衔接

```text
ai/domain/        Conversation、Turn、ModelEvent、Evidence、ChangePlan
ai/application/   AgentRuntime、InlineCommandService、AiCompletionService、ContextManager、ApprovalCoordinator、请求调度
ai/adapters/      ModelProvider、SSE parser、ConversationStore、OutputStore
ai/presentation/  对话、附件、执行/审批/验证卡片
```

按首个用例建立所需文件，不预建未使用的类。domain 纯 Dart；网络、文件、平台安全存储与第三方库留 adapters/platform。ai 只 import 其他 feature 的 api.dart，其他 feature 不反向 import ai。terminal 定义行内生成/补全所需的纯 DTO 与窄端口，由 app 将 AI 实现注入；不让 terminal 直接 import ai，也不将模型请求代码塞进纯规格引擎。app 组合层装配，不引入全局 EventBus。

三入口请求均标记 purpose、requestId、终端/授权/目的地 revision，所有回包经过来源相符的校验；行内/补全发送不含工具 schema，服务即便返回 tool call 也拒绝/丢弃，不导向 dispatcher。只有 Agent 的实际业务工具走 CapabilityDispatcher；本地意图识别、loading、候选排序和用户接受草稿不 JSON 化。

| 组成 | 职责与复用 |
|---|---|
| AgentRuntime | 只推进侧栏 Agent 的多步工具循环，单 turn 状态机、预算、取消树、工具结果配对、终态；不知道供应商 HTTP 字段 |
| InlineCommandService / AiCompletionService | 两种无工具的一次性生成；输入/输出使用各自受限 DTO 与校验，不进入 Agent 工具循环 |
| 共用请求调度 | Agent/行内/补全的来源优先级、全局网络上限、限频、取消；不合并三者的授权与上下文 |
| ModelProvider | 供应商请求/事件归一、用户触发的模型目录与私有续接材料；不调工具，不持业务权限 |
| 模型配置 | 单一选定协议/endpoint 与独立 Agent 默认、行内、补全模型；当前会话可临时选模型。目录 DTO 只含模型 ID/公开能力与限制，不含 Key |
| ContextManager | 来源追踪、数据发送过滤、预算、成对压缩、请求投影 |
| CapabilityDispatcher | 唯一工具执行业务入口；补 scope/审批/执行前重验，调用已有 handler |
| CommandExecutor | connections 的流式 exec 端口，typed 事件、双流、取消/期限；无 xterm/dartssh2 类型外泄 |
| 诊断采集端口 | 从 monitor 抽取可共享的纯解析/固定采集基础，新增独立授权的有限投影；不直接公开面板状态 |
| TerminalContextReader | terminal 的受限快照/选区/已知环境 DTO，固化 SessionId/generation/范围；不暴露 Terminal 对象 |
| TerminalDraftAcceptor | 用户接受生成命令/后缀的窄 typed 入口；检查空行或精确追加前缀、草稿代次与实际回显，无执行/删行参数；现有通用 insert 不能替代这些检查 |
| OutputStore | 工具输出与证据片段的唯一有界存储；句柄只索引已授权数据，不带任意文件路径 |
| Operation 记录 | capabilities/application 在执行前记 intent，执行后记终态；元信息审计与敏感输出分开 |
| ConversationStore | 版本化、脱敏且有界的文本历史；复用现有单写队列/损坏保护语义 |

当前已有一次性 `TransportLease.exec(... timeout, cancel)`，不适合假装实时流。新增流式接口应在同一连接适配层复用执行/收束核心，一次性调用继续保留原契约，不用轮询结果模拟流，也不调用私有 dartssh2 接口穿透模块边界。AI 先 acquire 租约，再启动单次执行；不能把命令包进 `ConnectionManager.open` 的自动重拨回调，该回调重试可能再次执行已发出的命令。

现有文件能力允许省略 hostId 访问本机，AI 投影必须要求显式远端 HostId，并提供真正有界的扫描/读取，不能直接导出旧入口的默认值。设置字段自身的 agentExposed 也不作为充分授权，需人工审阅的普通键白名单。workspace.split 会创建 shell，workspace.close 会结束 shell，不能统称可逆布局；纯 focus/比例变更才适用布局撤销。session.open/reconnect 用例返回已接受时只记 accepted，需观察相同 attempt/generation 的真实连接终态后才能记 connected。

当前监控是 UI 自有轮询、默认不发 AI。AI 固定诊断是另一个请求的所有者，有自己的租约、取消、字段白名单与发送授权；不暗中启动监控面板或把进程完整命令行送模型。共享的是采集/解析基础，数据权限和生命周期独立。

## 6. 模型配置与协议

首批支持 Anthropic Messages 与 OpenAI-compatible Chat Completions；两者分别实现协议适配，不拿 Chat Completions 冒充 Responses API。Responses 后续确有需求再加。兼容端点逐个建立契约样例；只支持普通文本的模型可用于行内生成、补全以及程序直接创建的空 scope 文本调用。Airy 的聚焦与主机发现流程使用工具协议，有效 Agent profile 始终启用工具协议，旧配置中的关闭标志也会归一；不会依据目录 ID 猜测能力或自动降级为无工具执行模式，服务不支持时明确失败。轻量入口的结构化结果可用供应商 JSON 输出能力，缺此能力则校验文本 JSON；无论哪种都由本地严格校验，不能假装供应商保证了语义正确。

用户可保存模型配置档：profileId、protocol、完整规范化 API 基址、model、contextWindow、maxOutputTokens、能力标志、timeouts 和 SecretRef。型号由用户选择/填写，不在业务代码固定某个当时最新型号。模型发现和连通测试由用户显式触发；失败保留手填能力，不伪造模型可用。

- AI key 通过独立用途的窄凭据端口保存，模型适配器按需取得；不复用翻译密钥引用。绑定完整目的地身份，改地址不能悄悄带走旧 Key。
- 云端默认 HTTPS，只允许明确 exact loopback 的本机 HTTP；无 userinfo/query/fragment。首版拒绝重定向，保持系统 TLS 校验。自定义 headers 不得覆盖认证、Host 或其他保留字段。
- API Key 的有效用途绑定选定协议/规范化 endpoint，同端点的模型目录、Agent、行内与补全模型共享已配置的用途专属凭据；持久引用沿用默认 profile.identity，不新增 endpoint-only 凭据格式。运行时为当前角色/会话模型取 Key 时，只在协议/规范化 endpoint 与已配置默认 profile 精确匹配后解析其凭据引用。设置中默认模型改变、endpoint/协议不变且没有新 Key/移除操作时，仅经窄凭据端口复制原有秘密至新默认引用，成功前保留原件；endpoint/协议变化绝不复用旧 Key，不扫描其他目的地。UI 不读取旧 Key 明文；用户新输入的 draft Secret 可经 typed 模型目录服务短暂用于本次获取，不进入模型目录 DTO、messages、工具、对话、错误详情或日志，不发送 SSH 凭据。模型完整 identity 仍参与历史数据目的地/在途批准绑定；配置或当前模型变化取消受影响请求并重验，旧历史不自动发给新模型/供应商。模型目录请求遵守同一 endpoint/TLS/禁重定向与取消/大小限制。
- 不自动更换供应商/模型。计费测试不在后台发生；首版不提供模型网络搜索、托管代码执行或其他绕开本地调度器的服务端工具。

| 协议 | 必须处理的语义 |
|---|---|
| Anthropic | message/content block 的 index、input_json_delta、stop_reason 与 message_stop；tool_use_id 对应紧接的 tool_result，多个结果成组返回，错误用协议错误字段 |
| OpenAI Chat Completions | choices/delta.tool_calls 按 index 聚合 id/name/arguments；role=tool 与 tool_call_id 配对；区分 stop/tool_calls/length/content_filter 与合法结束标记 |
| 统一事件 | textDelta、toolCallStart、toolArgumentsDelta、toolCallComplete、usage、messageComplete、error；provider 私有内容不塞进工具参数 |

SSE 使用增量 UTF-8，支持跨 chunk 字符/空行、CRLF、多行 data、heartbeat、流内错误。忽略已知协议允许的未知事件需有界且不改变完成判定。只有完整 assistant message、所有工具参数完成且 schema 通过后才执行，半截 JSON/length 截断/EOF 都不能触发工具。finish reason 与协议结束共同判断，不把断网当任务自然完成。

供应商要求的 thinking/signature 或其他 opaque continuation 原样保留在受限的活动协议状态，不展示为审批依据，不逐字输出所谓内部思考。不随意删改再重放；不能安全持久化/恢复时结束该续接，重新建立安全上下文。后续模型切换不能携带另一协议私有块。

正式参考：[Anthropic 工具结果](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)、[官方 SDK 流状态参考](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/lib/streaming/_messages.py)、[OpenAI Chat Completions 流事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)。实施时复核，不将文档示例型号或 SDK 默认预算当项目默认值。

## 7. 工具与确定性授权

不可委派权限权威定义见 [SECURITY §6](SECURITY.md)，调度顺序和审批字段见 [CONTRACTS §3](CONTRACTS.md)。模型只提出工具调用；授权、目标解析、参数验证、执行前重验、安全结果投影由代码完成。

### 7.1 工具目录

以下是设计名，只有真实 handler 和授权实现存在才注册；已有 Capability 并不自动向 agent 开放。一次请求只带当前模型能力、系统和授权需要的子集。Schema 首版只用受限 object/array/string/number/boolean/enum 与明确 required/长度/范围，拒绝未知字段和隐式类型转换；统一校验后再进入 typed handler，供应商 strict 不能替代本地校验。未知工具、无效参数、拒绝、取消都生成与原 callId 配对的安全错误结果；未被完整接收的消息不进入可重放历史。

| 工具组 | 设计能力 | 授权/投影 |
|---|---|---|
| 应用摘要 | app.getState、host.list、session.list | 仅发送时冻结的候选 ID/别名、状态、普通外观/布局；发现模式可含全部已保存主机 ID/别名，不返回账号、地址或认证配置 |
| 诊断 | diagnostics.collect | collectorId/version、固定主机、枚举参数、字段授权；命令源于代码模板，不接受自由 shell |
| 命令 | command.execute | 精确 host/cwd/command/deadline，执行按 §4.1 权限模式，输出发送单独处理 |
| 终端/输出 | terminal.read、output.read | session generation 或受权 handle + 范围；不能扫其他会话或已撤权历史 |
| 文件读取 | files.list/stat/read | 有限路径/范围、真实目标检查、敏感策略、发送预览 |
| 文件变更（M4d） | files.write/rename/mkdir/delete | 精确路径、基线/diff、符号链接策略、逐次审批；不可恢复删除显式说明，无通用撤销 |
| 传输（M4d） | transfer.enqueue/cancel/status | 本地与单一远端之间传输，明确源/目的路径、冲突策略、任务 ID；本地资源须用户选择授权，远程到远程复制仍按 M5 另议 |
| 主机管理（M4d） | host.create/update/move/delete、group 的已有用例 | 无秘密元信息、revision/引用检查；新/改变端点未自动获得连接范围，认证/信任仍用户处理 |
| 会话管理（M4d） | session.close、workspace.closeTabs | 绑定实际 shell 集合与代次，显示受影响项后批准；不关闭其他任务租约，不作为布局自动 undo |
| 转发（M4d） | forward.list/save/delete/start/stop | 复用已有 ID/typed 用例，精确两端/绑定地址/规则 revision，默认 loopback；停止列出受影响连接 |
| 长任务（M4d） | job.start/read/stop/status | 与精确执行同审批，jobId/owner/序列化 offset/TTL/未知结果，不能重启后自动执行 |
| 普通软件控制 | settings.get/patch、workspace.split/focus | 普通设置键白名单/expectedRevision；focus/比例可逆，split 创建 shell 需连接权限；不含端点/安全/凭据 |
| 会话 | session.open/reconnect | 只开用户选择过的 HostId；每跳信任和认证仍由用户流程处理 |
| 计划 | plan.update | 只更新进度草案；执行状态来自操作记录，不接受模型自报成功 |

M4d 是完整 Agent 的组成，必须逐项实现上述用例、授权与失败语义后才开放，不能仅注册工具名。工具目录随任务按需投影；模型可以请求提示某项受支持工具，但是否提供由本地 catalog/scope 决定，不让模型扩大工具集或授权。新增/改地址的 Host 草稿可经批准保存，不自动进入可连接 scope；删除核对跳板/身份/任务引用并显示影响。

本地文件通过用户文件选择器生成不可伪造的资源授权，绑定真实路径、类型、大小/基线、读/写用途和期限；模型拿 opaque ID，不能让任意字符串路径触发本机读写。模型提出“需要上传文件”可以展示选择入口，只有用户完成选择才执行。任意本地程序/网络请求、终端逐键写入、片段运行、监控结束进程仍无工具入口；获批 shell 的实际权限边界见 §7.3。

### 7.2 Scope、审批与发送权

Scope 由 UI/application 创建，至少带 purpose、conversation/turn 或短请求 ID、revision、精确 HostId/SessionId 或待解析的候选主机快照、允许能力/模板/字段/路径、有效期和模型目的地 revision；每次操作仍绑定 host 配置/路由/信任修订与连接 generation。连接变化不会自动沿用对旧连接批准的执行。

Agent scope 与轻量请求 scope 不可互换。行内点击只授权当次投影发送/生成；自动补全用户开关授予限定当前会话/主机、字段、目的地与有效期的后台发送，不是执行批准。行内生成和补全的功能开关包含所需的有限同会话历史投影，主机高级设置只筛选功能可用性，不另设历史或发送许可。三入口都无权修改这些策略。

权限有两个维度：**允许访问/执行**，以及 **允许把哪些结果发给哪个模型目的地**。模型、远端输出、标签、文件、摘要不能创建 grant。Agent 自主选择步骤不会扩大应用在发送时冻结的候选范围，也不能突破首个有效目标的锁定。

- 侧栏只有一个 Agent：发送时有聚焦 SSH 主机则只允许该 HostId；没有聚焦主机则冻结所有已保存主机的 ID/别名快照，须先调用 host_list，再根据用户对话明确一台，未指明或有歧义时反问。候选最多 1000 台，超限明确拒绝，不截断成伪完整列表。首次有效 HostId 在拨号前锁定，拨号失败也不能试另一台；模型不得添加候选或切换目标。确定目标后可用固定诊断，命令执行按 §4.1 的观察/确认/自动模式，默认确认。侧栏顶部只读显示目标。程序直接以默认空 scope 创建的文本调用保留纯对话语义，不等同于 UI 的发现模式。
- 固定采集器可按本次任务授予模板和字段权限，无须每个采样再弹窗；模板新增字段/命令或版本变化重新授权。
- 任意 shell 批准默认只允许执行；输出先在本地卡片预览，用户选定脱敏范围后发送。工具等待期间可展示等待数据授权，不自动把原文送模型。拒绝发送返回安全状态，不用另一工具/摘要绕过。
- 文件/终端内容同样先看发送范围；用户可明确对一项有限路径/行区间授权后续读取发送，不授无限目录/无限回滚权限。
- 一次批准绑定 capability/version、规范参数摘要、目标/账号/cwd、scope revision、配置/连接代次、输出发送范围、目的地与过期时间。编辑命令或模型重新提出不同参数均需新批准。
- 审批通过后在 handler 开始前再检查目标和修订；过期、断线、改路由、撤权、取消都使其失效。拒绝不自动重问同一动作，需用户新意图或实质不同方案。
- scope/目的地 revision 变化立即撤销旧批准，取消受影响的在途模型请求、读取与 exec；结果入库和发送前再次校验，迟到事件仅用于收束必要本地状态，不恢复发送权。已发远端命令仍可能结果未知，撤权不等于远端回滚。
- 撤销主机范围后，后续请求排除该主机证据、工具结果、附件、派生摘要/assistant 回答及 provider 私有续接材料。来源追踪覆盖整个活动上下文；不能可靠拆分时结束旧协议续接，开启干净上下文，让用户重新选择可发送输入。用户重新粘贴的文本也经发送预览，不以“普通文字”旁路已知来源限制。不声称能撤回供应商已经收到的内容。

### 7.3 执行权限的真实边界

固定采集器的受限性来自实现和参数白名单，不来自模型声称“只读”。任意 shell 按 SSH 账号实际权限执行，客户端审批不是服务器沙箱；即使命令名字常见，也可能读秘密、改文件或自行联网。shell 批准卡必须显示这一实际权限，不能宣称通过黑名单保障无副作用/无泄密。需要严格限制时只开放固定诊断，或由用户使用服务器侧受限账号。

类型化文件读取拒绝已知密钥、凭据与环境秘密位置，限制普通文本大小；规范化、真实路径检查、符号链接策略不能消除所有 SFTP TOCTOU，任意 shell 更不能复用该策略作为安全保证。输出发送经来源白名单、已知秘密匹配、结构化字段过滤和用户预览，regex 只辅助，不承诺发现所有未知秘密。秘密匹配只使用当前必要认证过程中已有的短期材料，不能为脱敏枚举/读取整个凭据库。应用持有的原始秘密始终没有 AI 读取端口；OutputStore 内尚未获发送权的字节也不能通过 output.read 或摘要旁路取得。

终端内容、采集结果、主机标签、文件、流程草稿和历史摘要全部是不可信数据，保持在数据块，不提升为 system 指令。系统提示描述工作方式，但不是授权边界。引用对象身份也必须由客户端验证，模型伪造 source/type/handle 无效。

## 8. 运行时、执行与停止

```text
idle → preparing → streaming → validatingTools → awaitingApproval
     → executingTools → awaitingDataApproval → recordingResults
     → preparing → … → completed
任意活动状态 → stopping → cancelled / outcomeUnknown
失败 → failed；重启遗留 → interrupted / outcomeUnknown
```

本节状态机属于 Agent，可跳过无必要的审批/执行步骤。每个 conversation 最多一个活动 turn，应用全局最多一个 Agent turn；轻量请求另走 `idle → eligible → requesting → validating → ready/abstain/error`，任意活动状态可取消/过期，不进入 executingTools。不同时运行多个自治 Agent。

每轮：固定已知目标或候选快照与输入 → 构建已准许发送的上下文 → 请求模型 → 收全消息与工具参数 → schema/工具目录校验 → 绑定操作目标与批准 → 执行前重验 → 写 operation intent → 执行 → 记录结果/数据发送选择 → 成对添加 tool result → 下一轮。模型多次修错也消耗同一轮次/工具总预算，拒绝循环不能无限继续。

**独立 exec + 可见执行卡**：每个执行持独立 channel/lease，不抢当前 vim/tmux/交互 shell。cwd 明确显示，cd/export 不会改变用户 shell；不隐式继承用户 shell 的环境。经过验证的 POSIX shell adapter 处理 cwd 引用，未知 shell/系统返回 unsupported。首版 Linux/Ubuntu，PowerShell 等单独适配后再支持。

stdout/stderr 各有增量解码器，保留各自次序；两流不声称全局严格顺序。输出进有界存储，超额继续排空并记丢弃量，不让内存随输出增长。无 exitCode 保持 null。交互输入/sudo 密码/TUI 由用户接管，首版不提供隐藏输入或自动答询；exec 不可用时明确失败，不静默改为向用户终端输入。

Agent Stop 是该 turn 的唯一取消协调入口：先撤销未决审批并停止派发，再取消该 turn 的 HTTP/所有自有工具、关闭已取得的执行 channel、取消订阅/计时器、归还租约，有界收束。没有新模型请求来“总结取消”；本地按已有事件列出各项状态。它不取消用户独立发起的行内生成，行内 Esc/取消也不停止 Agent。关闭侧栏不会停止 Agent；AI 总开关关闭或退出应用则取消三入口全部自有工作，退出接 ShutdownCoordinator。

取消、超时、断线分别记录原因；本地通道关闭不能证明远端全部子进程终止。状态至少同时表达客户端已停止与远端结果是否已知。不能为让 Stop 看起来成功去断共享 transport、杀用户其他进程或宣称回滚。dartssh2 应答前 session 不可取得等现有限制继续适用，见 CONTRACTS §1。

M4d 长任务使用 Agent 自有 exec/job，由 AgentRuntime 持有：jobId、operationId、固定目标、开始/期限、状态、输出 offset/截断、停止原因；start 不重复执行，read/status 无需启动新命令。停止仍只关闭自有 channel，不承诺进程树全部终止；到 turn 终态前收束全部 job，未证实终止的保留 unknown 与核实入口。不自动 detach，不跨重启续跑，不让后台服务器进程脱离所有者而冒称可管理。长任务预算受 §9 同一总期限约束。

后续专用可见 PTY 需单一输入所有权、显式接管、marker/退出状态、未知结果与资源实测，另行设计。无跨重启自动执行、定时无人值守或每隔几秒调用模型的持续监控。

## 9. 预算、上下文与内存

以下是设计初值，所有上限要在代码实现与 M4 测试后才能称生效；只在本节维护，避免各处默认值分叉。

| 对象 | 初值及超限行为 |
|---|---|
| 活动 Agent turn | 应用 1 个；关闭侧栏不增加名额；不阻止显式行内生成 |
| 三入口模型网络并发 | AI 三入口合计最多 2 个：Agent 最多 1 个，轻量通道最多 1 个；行内生成取代/取消自动补全，无活动请求则空闲，不预连 |
| 轻量请求触发 | 补全停顿 800ms，最小请求间隔 2s、最多 10 次/min 且 120 次/hour；仅焦点 pane，同草稿/上下文不重复；显式行内点击才发，不自动排队 |
| 轻量期限与输出 | 行内总期限 20s/最多 1024 输出 tokens，补全总期限 5s/最多 256 tokens；正常结果完全校验后发布，截断/length 直接失败或 abstain，不把流片段写进 shell |
| 轻量上下文 | 草稿/需求最多 4 KiB；环境最多 2 KiB；历史最多最近 8 条且合计 4 KiB，优先排除无关/敏感项；行内生成与补全均包含必要的有限同会话历史，原始输出不自动附加 |
| 轻量缓存 | 补全仅内存，最多 32 项且合计 128 KiB，TTL 30s；含 purpose/目标代次/cwd/草稿/历史/模型/授权修订的精确键；变更/清空立即失效，不跨会话复用，不落盘 |
| 生成文本 | 行内/补全完整命令同时不超过 2048 个 Dart UTF-16 码元与 4 KiB UTF-8，补全后缀另限 2 KiB；对齐现有单行候选字符限制，生成/候选/TerminalDraftAcceptor 用同一验证器，超限错误/abstain，绝不截断接受 |
| 模型/工具步数 | 每 Agent turn 最多 20 次模型请求、64 个工具调用；单次消息最多 8 个工具，超限保留部分结果后停止 |
| 并发 | 全局活动工具/长 job 合计 3；同主机任意 shell/副作用串行；多机诊断一次最多 5 台；本地 job.read/status/Stop 不等待工作名额，避免长任务阻塞取消 |
| 时间 | 命令默认 60s、单次最大 300s；模型流空闲 120s；活动工作 15min，用户等待单独计时，每次审批最多 5min；到期失效，重验后重新批准 |
| 协议缓冲 | 单 SSE 事件 256 KiB、单工具参数 64 KiB、单 assistant message 含私有续接材料 1 MiB；超限取消并报错，不带截断参数执行 |
| 模型输入 | 配置上下文默认 1M tokens，提供 256K 与自定义，最大输出默认 4096 tokens；当前按 `((contextWindow - maxOutputTokens - 2048) * 2).clamp(0, 2 MiB)` 估算可用字节预算，完整编码输入另受该预算检查。目录当前只有 ID，不自动推断模型限制；配置值不保证服务实际窗口，也不是精确 token 计数 |
| 压缩 | 输入达到预算约 70% 且存在可整理材料时自动整理，目标约 60%；只在完整 assistant/tool-result 组边界处理，保留当前用户请求、执行状态及来源/截断。当前使用本地确定性摘录，不另发模型摘要请求；通常保留最近完整组，必要时也将其转为摘要。供应商 opaque 存在时结束旧协议上下文，用有限摘要数据建立新上下文，不修改或重放旧签名。整理不重跑工具、不恢复授权，仍超预算则停止并保留可读记录 |
| 模型可见工具输出 | 单项默认最多 8 KiB 首尾片段；每请求所有工具片段合计最多 32 KiB，output.read 同受该累计限额 |
| 完整输出 | 单 execution 双流合计最多保留 2 MiB，全局 OutputStore 8 MiB；超额丢弃/驱逐并明确截断，首版不静默落完整输出 |
| 输出/证据句柄 | 绑定 owner/scope/目的地/代次与内容范围，空闲 TTL 30min；活动 turn 固定必要片段但仍受总量限制，不能保证永不过期 |
| 终端/文件输入 | 单次选区/快照最多 200 行且 32 KiB；单文本文件最多读取 256 KiB、发送仍分页和受输出预算限制；目录单次最多 200 条，明确截断 |
| 会话历史 | 本地最多 100 会话、30 天、总文本 50 MiB；每会话最多 200 项/1 MiB，按完整旧 turn 裁剪并标记，最新 turn 单独超限拒存；编码 JSON 文件另限 64 MiB，超大文件拒读写并保留原件 |
| 历史续传 | 明确继续后只发最近最多 32 项且编码数据块不超过 16 KiB，减少范围时标记 truncated；作为普通数据，不恢复旧协议消息/批准 |
| 历史加载与删除 | 首次打开 Airy 时加载有界本地文本，当前对话列表虚拟化；未发送草稿仅内存。删除历史不删除 operation 安全记录，不留会话备份；字节缓存与渲染对象另测，审计按 SECURITY §7 |

当前装配在请求前用完整供应商编码估算 UTF-8 字节，包含 system、工具 schema、消息与 opaque；未注入编码估算器时，本地估算另为每条 opaque 消息预留其 1 MiB 上限及结构开销。HTTP 适配器在读取 Key、联网前仍检查最终完整编码，防止估算路径遗漏。预算中的窗口换算不是精确 token 计数，也不保证服务端容量；不能因为配置写了大窗口就无限堆上下文。HTTP 413 与后续重试目标见 §10。

本地整理保留当前用户请求，将较旧完整工具组和此前获准续传的历史转为有来源、状态与截断标记的摘录。每段文字最多 256 UTF-8 字节，摘要集合以 8 KiB 为裁减目标；按预算移除最旧项并记录省略数量，必要时连最近完整组也转为摘要，不能丢半组。工具参数和证据 handle 不进摘录，摘要标为不可信数据，不把旧模型说法当执行事实；撤权后不能复活旧数据，不虚构已完成工作。

无向量库、全量终端索引、常驻 embedding 或本地大模型。启动不预加载会话；用户打开 Airy 后可查看本地历史，即使 AI 关闭也不因此发模型请求。AI 禁用期间取消现有任务，不建 HTTP 连接和模型轮询；历史正文与当前运行时投影的实际内存开销另测。

当前应用已有未定位的 Release 内存高峰，本设计不声称 AI 上线后可保证 200 MB。验收使用同窗口/同负载的开关对照、重复长输出/关闭任务的保留路径和长期平台期；有界字节存储不等于整个进程内存硬上限。

## 10. 重试、幂等、持久化与恢复

当前实现仅在请求前按 §9 自动整理，尚无 HTTP 自动重试；以下 429/5xx 退避与收到 413 后整理重发为后续目标，不能由本地整理已接入推断为已完成。

- Agent 的 429/5xx 仅在没有接受完整 assistant 消息、没有执行该响应的工具时重试，最多 2 次退避，遵守 Retry-After 和总预算。已流出的文字标中断，不与重试文字拼成一条；允许重试不等于供应商不会重复计费。轻量入口不自动重试：行内错误保留原文，用户明确重试；补全失败安静退回本地来源，至少冷却 30s 或更长 Retry-After，不在冷却结束后对原草稿自行重发。低确定性/abstain 是正常结果，不是失败重试理由。
- Agent 的 413 最多一次强制整理上下文再发；已完成工具使用已有结果，不重执行。轻量请求的 413 不自动压缩重发，行内保留输入供用户缩减/重试，补全冷却并退回本地来源。缺失输出返回 expired/truncated，不悄悄重跑原命令获取。
- operationId 由本地生成，不用模型 toolCallId/命令文本替代；同 operationId 完成返回已有结果，同 ID 进行中不启动第二份。用户明确再次执行相同命令用新 ID 和新批准。
- 执行前持久化 intent 元信息失败时，不发有副作用请求；完成结果落盘失败保留内存并提示。远端请求发出后无可靠结果标 outcomeUnknown，重启遗留 intent 先核实，不自动重放。SSH 不提供 exactly-once，不能承诺崩溃窗口消失。
- 为核实未知结果可提议新的检查，需当前授权；不能把检查伪装成“继续原写入”。同一 turn Stop 后恢复是新 turn，只带可用事实和未完成项，旧批准失效。
- 对话存于独立 `ai_conversations.json`，复用 schemaVersion/revision、单写队列和损坏保护；仅保存 §4.1 的有界文本投影，不保存完整工具输出、认证输入、私有协议签名或 Key。删除不留会话备份；当前提供单会话删除，尚无历史总开关或导出。辅助脱敏无法识别的秘密和业务敏感内容仍可能存在，本地文本不是加密保险箱。行内需求/生成、补全前缀/历史投影默认只在短期内存，不自动加进 Agent 对话或持久化/诊断；只有用户显式转 Agent 才附所选内容。AI 建议本身不记命令历史，用户实际提交后才按终端原规则记录。
- 对话历史删除/分支/编辑不会撤回服务器变更或已发送模型数据。普通设置和不涉及 shell 生命周期的布局变更，在补齐公开 revision/before-after 契约后提供撤销；不能暗示当前 workspace 已有此能力。split 新建 shell，自动撤销不能直接关闭它；shell/删除/断线/补偿不提供通用 undo。
- OutputStore 默认内存，应用退出后完整引用可能不可用；历史显示证据摘要和“原始输出已过期”。完整输出导出需用户显式选择，经预览保存；默认不为了引用永久保留原始服务器数据。
- 审计只记时间、来源、目标 ID、capability/version、operationId、批准/拒绝/结果码与必要不可逆参数摘要；命令和输出不写普通诊断日志。摘要不能用来反查秘密，含秘密参数不进入审计载荷；审计不构成可抗本地 OS 用户篡改的取证系统。

## 11. 首批诊断模板

固定模板由客户端维护版本，服务端无需安装 agent。第一批 Linux/Ubuntu：

| 模板 | 输入与输出 | 限制 |
|---|---|---|
| system.summary | OS/内核/架构、uptime、负载、内存容量、两次 CPU 样本 | 默认不含环境变量、完整地址、进程参数；缺权限/不支持记缺失 |
| storage.capacity | 文件系统类型、总量/可用量、获准发送的挂载点 | 不递归 du，不扫描用户目录；路径属于发送范围的一部分 |
| service.state（后续小步加入） | 用户选择的服务标识 → active/sub/result 等固定字段 | 仅验证过的 systemd adapter，参数经专用引用/校验；不含 restart，不自动读完整 status/log |
| file.metadata / text.range | 用户指定路径的 stat / 有界文本片段 | SFTP 权限/真实目标/敏感路径/预览；不以文件名命令拼接读取 |

不一次创建十几套“智能专家”。网络/DNS、进程细查、日志时间窗、容器等在有真实需求后增加确定输入/输出；生成 shell 仍走 command.execute，不能借 collector 接受任意命令片段。采集失败保持 unknown，不让模型猜成健康。

## 12. 完整 Agent 的远程文件写入（M4d）

此项属于完整目标，不阻塞 M4b 首个可用版，未实现不得称完整 Agent 已完成。提供前至少满足：用户选定路径/目标类型、敏感路径策略、原内容基线、小文本上限/编码保持、可审阅 diff、批准绑定新内容摘要、提交前重读、目标旁暂存与安全发布、失败原件/稿件保护、验证和恢复入口。不得经 settings.patch、上传工具或任意本地文件接口旁路开放。

备份不能放到意外可读的公共目录，目录/权限由适配器验证，无法保护就拒绝。SFTP stat/read/rename 缺少通用原子 CAS，仍可能被其他进程改动；回滚前重新比对“当前是否仍等于本次写后内容”，不覆盖他人的后续修改。备份成功不代表修改成功，恢复是新批准动作。

## 13. 实现顺序与验收

| 步骤 | 具体工作 | 完成条件 |
|---|---|---|
| M4a-1：共用底座 | AI 配置/窄凭据，两种协议、SSE/取消/轻量调度，侧栏文本解释；总开关、独立功能开关与可用主机筛选 | A-01/13；无工具模型服务生成但不能执行，关 AI 无请求 |
| M4a-2：行内生成 | 本地三态识别、pane 图标/快捷键、原位加载、单次结构化生成、可编辑预览/空行接受；显式本地输入层 | A-10/11；不盲清远端行、不插 Enter，旧结果/未知内层身份不回填，IME 不误触 |
| M4a-3：AI 补全 | 意图门槛、停顿/限频、同会话历史投影、abstain、纯后缀候选顶置、保留选中项 | A-12/13；不硬补、不猜存在、开关前无发送，迟到结果不抢 Tab |
| M4b-1：Agent 执行底座 | dispatcher scope/revision/deadline/审批/安全 DTO；operation intent；流式 exec/受限快照/OutputStore；接 Shutdown | A-02/03/04；未知目标/过期批准拒绝，Stop 不断共享连接，重试不重放 |
| M4b-2：Agent 诊断 | 固定 system/storage 采集、独立数据发送权、Evidence 引用、命令/文件结果预览，单机诊断闭环 | A-06 的单机部分；伪造引用无效；拒绝发送后请求不含原文 |
| M4c：应用与差异 | 普通设置/布局/会话、冲突撤销、5 主机上限比较、变更前后验证、历史/导出、资源测量 | A-05/06/07/08；部分失败如实展示，执行 0 不等于修复，三入口资源均有界 |
| M4d：完整 Agent 业务 | 主机/组/会话管理、远程文件写入/操作、受授权本地资源的传输、转发、受管长任务；可复用诊断流程 | A-09/14；逐工具契约/审批/失败/恢复验证，文件与任务不借任意 shell 掩盖缺少 typed 能力 |
| 按反馈扩展 | 专用可见 PTY、更多系统/采集器、有明确范围的自动模板模式 | 另补契约/失败验收；窗口权限模式见 §4.1；不附带无人值守调度 |

首个架构交付接通模型配置/凭据、两协议、单机固定诊断及逐次获批 exec 的闭环；侧栏助手 Airy 不提供解释/诊断/执行模式、工具开关或主机下拉；发送时冻结聚焦 SSH 主机，无聚焦目标时按 §4.1/7.2 先查已保存主机并明确单一目标，未明确则追问。模型目录当前仅提供 ID，不推断能力元数据；服务不支持请求的工具格式时明确报错，不以能力推测跳过本地授权。配置共用选定协议/endpoint，分别保存 Agent 默认、行内与补全模型，聊天可选择当前模型；每次用户发送建立新的 turn/协议上下文，Airy 的本地历史与显式有限续传按 §4.1，不自动携带前一 turn 的派生内容或旧批准。网络失败暂由用户显式重发新 turn，不自动重试；上下文占用以与预算一致的字节启发式换算展示估算比例，不能冒充供应商实际 token 计数；发送前、完整回复和整理后更新，清空/恢复时重置。自动上下文整理按 §9 接线与验收，完整 HTTP 退避及更完整的恢复/导出按后续验收推进；轻量请求使用 §9 的独立通道、行内优先、限频与取消规则。审批和等待发送计入首版 15 分钟总期限，单工具串行（低于全局并发上限），不预建并行 job。行内生成与自动补全按 §4 的独立功能开关、主机可用性与验收接线，不以空接口代替完成；M4c/d 继续按独立验收推进。首版 Agent 每 turn 只操作一台已保存的 SSH 主机，本地 PTY 不开放执行；分屏焦点只确定本次单一目标，不能作为整个标签所有会话的授权身份。后续工作区工具须解析全部实际受影响会话再批准。

执行批准绑定已取得租约的不可变连接身份（transportId、完整路由/安全修订快照），执行前复验当前解析结果与该租约；不自动重拨和重放。未知信任/认证由既有用户流程完成，后台诊断拒绝交互挑战。Scope 或目的地变化终止旧 turn 和协议上下文；本地历史只供查看，不跨供应商继续旧会话，目的地/主机/路由变化后的发送新建会话。操作 intent 只存 ID/目标/能力/状态等元信息，未决恢复标未知且不重跑。输出默认内存有界，任意命令输出先在本地选择发送，拒绝后模型只收到状态。

终端窄端口以 SSH/local typed 目标、session generation、草稿 revision 和实际回显为基础；生成首版采用显式本地输入层，不承诺现有单行解析器能证明任意 shell/pipeline 的语义。没有经过适配验证的 shell/系统拒绝自动回填和 cwd 引用；用户批准任意远端 shell 的真实权限仍见 §7.3。

第一批改动落点：`features/ai/` 的共用接入及三种服务；`features/capabilities/` 的描述/dispatcher 与装配；`connections/api.dart` 及 exec 适配层；`terminal/api.dart` 的上下文/历史窄投影、接受命令端口与 provider 注入，terminal 的本地识别/行内 overlay/候选排序与失效检查；monitor 的采集/纯解析公共端口；files 的受限读取 façade；settings 与 credentials 的独立用户配置/窄用途端口；`app/` 的注入/关闭、侧栏与快捷键；`design/` 只补确实缺少的通用控件；`l10n/` zh/en。M4d 再按需扩主机/传输/转发/文件公开用例，不重写 SSH/SFTP/设置核心或开放全部内部类。

测试方法遵守 [TESTING §1–2](TESTING.md)：协议/授权/结果未知使用纯逻辑和内存替身；只有实网协议、真实 SSH 取消与共享资源等必要环节使用作者环境。真实模型 Key、计费请求或服务器写入需对应授权，首版诊断不在作者服务器结束进程或重启服务。验收编号只在 TESTING 定义，本文不记录未运行的通过结果。
