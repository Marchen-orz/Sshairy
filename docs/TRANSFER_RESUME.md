# 单文件暂停与续传（M3）

实现依据：MODULES §4、SECURITY §5、TESTING F-04。本文先定义本轮行为；实际验证状态见 ROADMAP，不将设计当成通过结果。

## 范围与状态

仅普通单文件支持暂停/续传；目录继续使用现有扫描、逐项冲突与取消，不支持目录 checkpoint。源文件必须能提供 size 和 mtime，缺少这些字段时仍可从头传输，但不开放暂停。queued → running → pausing → paused；手动恢复重新进入队列。程序正常退出中止单文件后为 interrupted，已落盘的有效 checkpoint 可在重启后由用户恢复，不自动拨号。

暂停停止继续读取源，但等待已发出的写入完成并关闭文件句柄，再 stat .part，记录稳定长度。不能把 SFTP writer.abort() 的立即返回当作写入已收束。取消则实际终止写入并清理本任务拥有的 .part。目录不保留续传资源。

## Checkpoint

transfers.json 保持 schemaVersion 1，新增可选 checkpoint 和 directory 字段；旧任务无 checkpoint 仍可从头重试。checkpoint 保存源大小/修改时间、实际目标路径、.part 路径和稳定长度，以及替换目标原来的大小/mtime。完成、取消并清理后移除 checkpoint。

.part 只能是原目标同目录下、由实际目标名和本任务 ID 派生的隐藏文件；实际目标只能是原目标或同目录合法的“保留两者”名字（与分配器一致，序号 1–999）。任务 ID 限定为 1–128 个 ASCII 字母、数字、下划线或连字符；读取历史时验证，非法 ID 或无法解析的 checkpoint 使配置读取失败并保留原件，不能静默丢记录、丢 checkpoint 或初始化空历史。生成 .part 前及恢复/清理前再次验证 ID、派生关系和父目录，运行中取消也不跳过检查。恢复数据必须验证这些约束，绝不信任历史 JSON 提供的任意删除路径。链接、目录、负长度、超过源大小的 .part 都不是有效 checkpoint。

只要有 checkpoint，先走单文件恢复校验，再决定任何文件操作；源变成目录或链接时返回 sourceChanged，保留 checkpoint 与 .part，不扫描新目录。只有显式从头重试并成功清理暂存文件后，才能按新的源类型开始。取消用例等待实际任务收束或暂停文件清理后才返回。

复制期间的 checkpoint 标记为未收束；只有正常暂停/退出已经等待写入完成、验证源与 .part 后才标记可恢复。突然杀进程或网络故障可能留下未收束文件，无法证明连续前缀时拒绝续传，允许显式取消/从头重试；不宣称任意崩溃都可无损续传。

## 恢复与资源保护

恢复前重新 stat 源：类型、大小或修改时间不同则 sourceChanged，绝不追加。再检查 .part 是普通文件，长度与稳定 checkpoint 完全一致且不超过源大小，否则 partInvalid。源从该偏移读取，目标只向已存在、长度匹配的 .part 追加，不截断、不创建缺失的 .part。最终再次核对源身份和结果长度，最后沿用原子发布与替换前目标基线检查。size/mtime 不能识别伪造相同元数据的内容变更；哈希一致性由测试验证，不宣称传输自身进行全量哈希校验。

暂停/中断任务保留目标锁，不占用传输并发和 SSH 租约；同路径的新任务等待旧任务恢复、完成或明确清理。带 checkpoint 的历史不能因普通“清空已完成”或时间裁剪被悄悄丢弃；显式移除/从头重试先安全清理 checkpoint 指向的本任务暂存文件，清理失败保留记录并显示路径。目录不清理测试目录以外的任何文件，测试只用临时目录和模拟远端。

FileSystem 只新增偏移读取与已有文件追加的窄接口。SFTP 固定 32 KiB 请求；暂停通过停止源流并等待 writer.done 收束在途请求，不关闭共享 transport。文件句柄验证无法消除其他进程在 stat 与 open/rename 之间改动路径的所有竞态，保持 SECURITY §5 的已知限制。
